B) UPLOAD-PATH ALLOCATION (master-only, fail-closed 503)
   - GOAL: assign URL path prefixes to specific nodes so /upload/users ->
     slave-1 and /upload/files -> slave-2 (split file traffic across
     file-role nodes), instead of round-robining everything.
   - NEW config field: ClusterConfig.pathPins? = Array<{prefix, nodeId,

     round-robin fallback). Else route to that node's services[role] ||
     baseUrl. Auth paths (/auth/*, /csrf-token) are never path-pinned
     (auth anchor wins). setPathPins(pins) updates routing live.
   - manager.ts: passes config.cluster.pathPins into the LB; setPathPins()
     exposed so the admin can update without an LB restart.
   - POST /admin/cluster/setup EXTENDED: accepts pathPins, validates +
     normalises (drops empty prefix/nodeId, coerces role enum), persists
     to nexus.runtime.json, applies live via manager.setPathPins().
   - GET /admin/cluster/overview now returns pathPins.
   - App.tsx master panel: NEW "PATH ROUTING" section under the node
     cards. Table of pins: prefix (input) -> nodeId (dropdown of linked
     node ids) + role (optional dropdown) + "node down" badge if the
     pinned node isn't ready. Add/remove rows, "Save routing" ->
     saveClusterSetup({}, pathPins). Empty state: "No path pins - all
     traffic round-robins across ready backend nodes."
   - api.ts: ClusterPathPin type, saveClusterSetup(master, pathPins?),

## 1. Cluster Panel Redesign (all 4 projects)

### Problem
Admin panel showed "Unauthorized" when clicking "Link node". Root cause: CSRF cookie rotation race — 5-second overview poll rotated the CSRF cookie between `refreshCsrf()` and the POST.

### Solution
- Redesigned cluster panel with master/slave mode toggle
- Per-node pairing tokens (each slave generates its own token)
- Fixed CSRF cookie rotation race (reuse existing cookie, don't rotate on every safe request)
- Error messages now persist until next button click (separate `pollError` from `msg`)

### Files changed (per project, 28 total across 4 projects):
1. `packages/nexus-cluster/src/types.ts` — added `authToken?: string` to `RegistryNode`
2. `packages/nexus-cluster/src/registry.ts` — `setToken()`, per-link token in `link()`, stored `authToken`, used in `poll()`/`clientFor()`
3. `packages/nexus-cluster/src/manager.ts` — `link(agentUrl, token?)` passes token through
4. `apps/backend/src/modules/admin/clusterRoutes.ts` — `/link` accepts `token` in body + `POST /admin/cluster/generate-token`
5. `packages/nexus-admin/src/api.ts` — `clusterLink(nodeUrl, token?)` + `generateClusterToken()`
6. `packages/nexus-admin/src/App.tsx` — full `Cluster()` redesign (master/slave toggle, slave token gen, master pairing dialog) + error message persistence fix
7. `packages/nexus-auth/src/csrf.ts` — stop rotating CSRF cookie on safe requests

## 5. API Key Persistence to .env (bhooai-nexus)

### Problem
API keys were stored only in-memory (lost on restart).

### Solution
- **Write to .env**: When setting an API key via admin, it's persisted as `NEXUS_AI_<PROVIDER>_API_KEY` in `.env`
- **Read from .env at boot**: `schemaRoutes.ts` loads keys from `process.env` into in-memory providers
- **Fallback**: Also checks `<PROVIDER>_API_KEY` (e.g. `TOGETHER_API_KEY`) for compatibility
- **Mutable array**: `main.ts` clones the frozen config array and passes the same mutable reference to both `registerAiRoutes` and `registerSchemaRoutes`

### Files changed:
1. `apps/backend/src/modules/admin/schemaRoutes.ts` — `writeEnvKey()`, `readEnvKey()`, `deleteEnvKey()`, `providerEnvKey()` helpers; updated PUT/POST/DELETE endpoints
2. `apps/backend/src/modules/admin/adminRoutes.ts` — added `aiProviders` to `AdminRouteDeps`, passes `root` to `SchemaAIConfig`
3. `apps/backend/src/main.ts` — creates mutable `aiProviders` clone, passes to both routes
4. `.env` — all 20 `NEXUS_AI_*_API_KEY=` variables (empty placeholders)
5. `packages/nexus-cli/src/commands/init.ts` — `AI_PROVIDER_ENV_KEYS` array + `ensureAiProviderKeys()` function

## 6. Framework Dependency (no more packages/ copy)

### Problem
Each project had a full copy of `packages/` from the framework (duplicated source, hard to sync changes). User deleted these folders.

### Solution
Projects now point npm workspaces directly at the framework's `packages/` directory:

```json
"workspaces": ["../BhooAI-Nexus/bhooai-nexus/packages/*"]
```

This creates symlinks `node_modules/@bhooai/nexus-core` → `framework/packages/nexus-core`.

### Files changed:
1. `bhooai-nexus/package.json` — added subpath exports for all packages
2. Template `package.json` — workspaces → framework, added `bhooai-nexus` file: dep
3. node-1, MyFirstProject, social-network `package.json` — same changes
4. `packages/nexus-cli/src/commands/init.ts`:
   - Removed `vendorFrameworkPackages()` (stopped copying packages into projects)
   - Removed `FRAMEWORK_PACKAGES`, `PRUNED_PACKAGE_DIRS` constants
   - Added `wireFrameworkDependency()` — sets up correct workspace paths + file: dep

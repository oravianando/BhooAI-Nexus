LEARN · 01

Foundation The workspace, the config system, DI, errors, and the custom HTTP server. Everything else in Nexus builds on @bhooai/nexus-core.

This chapter reconstructs the lowest layer of the framework. It is deliberately without express/fastify/koa: the HTTP server is hand-rolled on node:http, the config loader is own code with a zod schema, and the DI container is a few hundred lines.

Why this package first

Every other package imports from @bhooai/nexus-core:

  • nexus-auth uses Router, RequestContext, Middleware, and AuthenticationError.
  • apps/backend/src/main.ts builds a Router, a NexusServer, and loads config with loadConfigAuto.
  • The CLI and admin read the same config stack.

Code walkthrough

1. The router — trie dispatch

The router is a trie: each path segment becomes a node, with special handling for :param and * segments. Registering a route:

router.get('/users/:id/publish', handler, [authToken, requireRole('user')]);
router.post('/echo', (ctx) => ctx.json({ received: ctx.body }));

Internally, add() walks the path and builds nodes:

add(method, path, handler, mw) {
  const node = this.findOrCreateNode(path);
  node.handlers.set(method.toUpperCase(), handler);
  for (const m of mw) node.middleware.push(m);
  return this;
}

Matching collects route-level middleware into collectedMw and resolves params. If a path exists but the method doesn't, it returns a 405 handler that advertises Allow — a nice touch most frameworks leave to the client.

Middleware order Router-level middleware via router.use() runs before route middleware (they are collected first in match()), which in turn runs before the handler.

2. The server — middleware pipeline

NexusServer wraps node:http. The constructor accepts middleware and a router. On each request it builds a RequestContext, propagates an x-request-id, and runs the pipeline:

async runPipeline(ctx) {
  const stack = [...this.middleware, this.dispatchMiddleware()];
  let i = 0;
  const next = async () => { const mw = stack[i++]; if (mw) await mw(ctx, next); };
  await next();
  if (!ctx.res.writableEnded) ctx.status(404); // nothing wrote -> 404
}

The dispatch middleware matches the router, sets ctx.params / ctx.routePattern, then runs route middleware + handler. Note the direct access to ctx.res — this is what lets the AI proxy write SSE chunks by hand.

3. Context

RequestContext wraps the raw req/res and exposes ergonomic helpers (ctx.json, ctx.status, ctx.query, ctx.body, ctx.state). Raw body is kept on ctx.state.__rawBody for webhook signature checks.

4. Config precedence

Precedence is low → high: defaults < nexus.config.ts < nexus.runtime.json < .env/NEXUS_* < CLI flags. loadConfig applies each layer with merge(), then validates the result against the zod schema (so typos surface early).

const config = await loadConfigAuto({ root: process.cwd() });
config.server.port;  // number
config.db.uri;       // validated as mongodb://...

5. Errors

Handlers throw typed errors (ValidationError, AuthenticationError, ConflictError, …). toNexusError normalizes anything thrown (including unknown values) and the server emits { error: { code, message, details? } }.

Why no express? A trie router + middleware pipeline is ~300 lines. By owning it, Nexus controls error envelopes, request ids, SSE access, and 405/404 behavior without a framework's assumptions.

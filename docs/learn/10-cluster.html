Cluster @bhooai/nexus-cluster — multi-host mesh. A node agent on every machine, a persisted central registry, a round-robin load balancer, and an RPS/CPU autoscaler with an optional AI advisor.

Code walkthrough

1. Load balancer — round-robin

The LB is a plain node:http reverse proxy. It round-robins across every ready backend node and streams requests through untouched (so SSE and uploads work), tagging each response with x-bhooai-node:

private nextTarget() {
  const targets = this.targets();  // registry.readyByRole('backend')
  if (targets.length === 0) return { id: '', baseUrl: '' };
  const target = targets[this.rr % targets.length];
  this.rr = (this.rr + 1) % targets.length;
  return target;
}

It also keeps a per-node request counter + a 10-second histogram — that's the autoscaler's RPS source.

2. Registry + agents

NodeAgent runs on each host, announces its services (backend, frontend, …), and heartbeats to the central NodeRegistry. The registry is persisted so the mesh survives restarts and can fail open when single-node.

3. Autoscaler

Autoscaler watches RPS per node and CPU; on thresholds it scales within minNodes/maxNodes with cooldowns. ai.ts is an optional HttpAiAdvisor that can inform the decision.

4. In the backend

ClusterManager auto-starts the LB + autoscaler when cluster.enabled (config). The admin console exposes full mesh control via /admin/cluster/*.

Fail-open When cluster.enabled is off (default) or the mesh is down, the app keeps working on a single node — a deliberate availability choice.

Playground

Sandbox: round-robin target selection + autoscale-decision model. Live API: the backend health (mesh control endpoints are admin-authenticated).

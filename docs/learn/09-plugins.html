Code walkthrough

1. Manifest + capabilities

A plugin declares name, mode (trusted | sandboxed), and the capabilities it needs (http, graphql, data, fs, net, …). In sandboxed mode, every registrar is gated by these:

const manifest = {
  name: 'analytics',
  version: '1.0.0',
  entry: 'index.js',
  mode: 'trusted',
  capabilities: ['http', 'admin'],
  hooks: ['init', 'start'],
};

2. Trusted vs sandboxed

  • Trusted — runs in-process with the full Node API. Used for subgraphs (resolvers aren't serializable across a worker boundary — a documented seam).
  • Sandboxed — runs in a worker_threads with heap/event-loop isolation, capability-restricted RPC, and a heartbeat watchdog that kills a stalled worker.

3. Host + lifecycle

host.ts loads manifests, builds HostBindings from the running services (router, realtime, logger), validates config against configSchema, and runs plugins in dependency order. apps/backend/src/plugins/loadPlugins.ts wires it into the backend.

Honest seams Sandboxed plugins can't add GraphQL subgraphs or middleware (functions aren't serializable). Use trusted mode for those. The sandbox is capability-gated, not cryptographic.

Playground

Sandbox: manifest validation + a capability check. Live API: list the backend's plugin extensions.

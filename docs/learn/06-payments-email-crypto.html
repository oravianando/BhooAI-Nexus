Code walkthrough

1. One interface, five gateways

Every provider implements PaymentProvider — createOrder, capture, refund, getOrderStatus, verifyWebhook. Amounts are in major units (e.g. 10.50); Razorpay converts to paise internally via toMinor. The HttpTransport is injectable, so tests mock the gateway without live keys.

2. Activating providers

const active = (cfg, keys) => cfg?.enabled ?? keys.every((k) => typeof cfg[k] === 'string' && cfg[k].length > 0);
if (active(config.razorpay, ['keyId', 'keySecret'])) providers.set('razorpay', new RazorpayProvider(config.razorpay));

Adding keys (or setting enabled: true) activates the provider — a user who configures keys without the flag still gets a working gateway.

3. Verified webhooks

WebhookRouter verifies the raw body (kept on ctx.state.__rawBody) against the provider signature, rejects with 401 on mismatch, and ACKs 200 so the gateway doesn't retry:

const event = await provider.verifyWebhook({ rawBody, headers, params: ctx.params });
if (!event.verified) { ctx.json({ error: 'signature verification failed' }, 401); return; }
try { await this.onEvent(event); } catch { ctx.json({ ok: false }, 200); return; }
ctx.json({ ok: true }, 200);

4. Email

createEmail(config) returns an EmailService. provider: 'log' never sends (dev); smtp uses nodemailer. Templates register named bodies and the queue retries.

5. Crypto / CSR

node:crypto makes keys and certs but not CSRs. csr.ts builds the CertificateSigningRequest structure with a hand-rolled der.ts encoder — no node-forge dependency.

Playground

Sandbox: the toMinor amount conversion + webhook verify model. Live API: create a Razorpay order (needs keys in .env; otherwise the error path is informative).

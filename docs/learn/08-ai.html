AI Server The Python FastAPI gateway (OpenAI + Ollama) behind a single contract, plus the Node client that calls it. Browser → Node proxy → Python → upstream, with SSE re-emitted end to end.

The flow

Browser ──> Node backend (:4000) ──> Python FastAPI (:8000) ──> OpenAI / Ollama
                  proxy /ai/*              providers/base.py
                  re-emits SSE

File map — apps/ai-server (Python)

Code walkthrough

1. Python — one provider, two backends

OpenAI and Ollama expose the same API shape, so a single Provider parameterised by base URL + auth handles both. The provider routing field is stripped before forwarding upstream:

async def chat(self, body):
    async with httpx.AsyncClient(timeout=self.timeout) as client:
        resp = await client.post(f"{self.base_url}/chat/completions", json=self._clean(body), headers=self._headers())
        resp.raise_for_status()
        data = resp.json()
        data["provider"] = self.name   # tag which backend answered
        return data

2. Python — SSE streaming

chat_stream consumes upstream data: lines, re-injects the provider field, and re-emits them. The FastAPI route wraps it in a StreamingResponse.

3. Node client

AiClient does fetch + exponential-backoff retries on network errors / 5xx / 429, with an AbortController timeout. chatStream yields parsed chunks from parseSseStream.

4. Node proxy

apps/backend/src/modules/ai/aiProxy.ts exposes /ai/chat/completions etc. and re-emits the SSE so CSRF + auth stay in Node. The browser never calls Python directly.

5. The contract

contracts/ai-openapi.yaml is the single source of truth for the Node↔Python boundary — it prevents drift between the two terminals.

Playground

Sandbox: an SSE parse + provider-select model. Live API: list models or run a chat completion against a running AI server (needs AI_OPENAI_API_KEY or Ollama; otherwise the upstream error is shown).

Code walkthrough

0. Wizard primitives

src/wizard.ts provides the shared interactive primitives used by every interactive command. Built on node:readline/promises (no new deps):

  • isInteractive() — true when process.stdin.isTTY && !process.env.CI.
  • prompt(question, defaultValue?) — free-text input; returns default when non-interactive.
  • confirm(question, defaultValue?) — yes/no (y/n); defaults when non-interactive.
  • select(question, options, defaultValue?) — 1-indexed list choice.
  • multiSelect(question, options, defaultValues?) — comma-separated multiple choice.
  • promptHidden(question) — API-key / secret input (dev-only — non-interactive returns '').
  • banner(title, lines) — prints a section header.
  • summaryTable(rows) — label | value table with green/red status icons.
  • statusIcon(ok) — ✓ / ✗ in green/red.

Every prompt returns its default in non-interactive mode, so the wizard stays scriptable (--no-interactive + flags for CI).

1. nexus init — all-in-one wizard

The most heavily used command. When stdin is a TTY it runs a 20-step interactive wizard; when it isn't (CI, piped input) it operates entirely from flags with sensible defaults. After one run, npm run dev starts the whole stack — backend, frontend, admin, Python AI server, Mongo + Redis wired, JWT secret + AI keys in .env, cluster token generated, and the project pre-registered in nexus_projects.projects.

Key features:

  • Prerequisite scan (shared with doctor) — detects node/npm/python/git, probes Mongo + Redis via TCP. If Mongo/Redis are down, offers retry/continue/abort so you can start them in another terminal and re-probe without aborting the wizard.
  • Auto-detect cluster token — when scaffolding a node next to a root project, detectSiblingRootToken() scans the parent directory for a sibling nexus.config.* with cluster: { enabled: true, token: '...' } and reuses it — so the node can authenticate to the central immediately.
  • Pre-registration — writes a record into nexus_projects.projects (status 'stopped', full settings snapshot, no secrets) so the admin dashboard recognizes the project before the first npm run dev. The backend flips it to 'running' on startup.
  • Security invariants — Python AI server binds 127.0.0.1 (AI_HOST in .env) so only Node (same host) reaches it. Secrets stay in .env only. The verify step asserts loopback and port-free checks.
  • Idempotent — re-running nexus init . updates config + .env without clobbering existing secrets or regenerating the cluster pairing token.

How to use — practical examples

Quick start (interactive)
# Run the wizard — answer prompts with defaults or enter custom values
nexus init my-app
# Walk through: project name → root/node → ports → Mongo/Redis → AI providers → venv → confirm → done
cd my-app && npm run dev
Scaffold a node that pairs with an existing root
# The wizard auto-detects the sibling root's cluster token so nodes can link immediately
cd my-cluster
nexus init root-server --as=root
nexus init slave-1 --as=node --role=backend --port=7575
# Start the root and node, then link from the root:
cd root-server && nexus cluster serve
cd slave-1 && nexus node serve --role=backend --port=7575
nexus cluster link http://localhost:7575
CI / non-interactive (one-liner)
# All values from flags — no prompts, no TTY needed
nexus init ci-app --no-interactive --name ci-app \
  --mongo-uri mongodb://localhost:27017/ci-app \
  --redis-url redis://localhost:6379 \
  --ai-providers ollama,openai \
  --ai-key openai=sk-your-key-here \
  --venv \
  --skip-install    # skip npm install (CI does it separately)
Re-run in an existing project (idempotent)
# Updates config + .env without clobbering secrets or regenerating the token
nexus init . --no-interactive --name my-updated-app --mongo-uri mongodb://localhost:27017/new-db
Custom ports (avoid collisions with another running project)
# The wizard auto-allocates free ports. Pass --no-interactive to force defaults,
# then edit nexus.config.ts to set custom ports before the first npm run dev.
nexus init app2
# or override ports in a single command (edit nexus.config.ts after):
nexus init app2 --no-interactive --name app2
# then in nexus.config.ts: server: { port: 4010 }, frontend: { port: 3020 }, admin: { port: 3012 }
GitHub Codespaces / cloud (no Mongo/Redis locally)
# Skip the Mongo/Redis probe so the wizard doesn't block on reachability
nexus init cloud-app --skip-mongo-check
# Or set remote URIs in one go:
nexus init cloud-app --no-interactive \
  --mongo-uri "mongodb+srv://user:pass@cluster.mongodb.net/myapp" \
  --redis-url "redis://my-redis.cloud.com:6379" \
  --skip-mongo-check

2. nexus uninstall — remove a project cleanly

Three-step cleanup that removes a project from disk + the databases:

  1. Drop the project's MongoDB database (e.g. test_app) — reuses the project-info connection's MongoClient so no second connection is needed. Skipped with --keep-db or if Mongo is unreachable.
  2. Delete the project's record from nexus_projects.projects (the shared registry — other projects are untouched).
  3. Optionally purge files — only with --purge. Handles Windows EPERM on read-only node_modules/.bin and .venv files via a three-layer fallback: (a) recursively chmod to clear the read-only bit, (b) rmSync with 3× retry, (c) OS shell rd /s /q on Windows / rm -rf on Unix.

Refuses to run non-interactively without --force. --dry-run previews everything without deleting.

Instead of concurrently/pm2, Nexus ships its own supervisor. It spawns the four services with prefixed colored logs, handles Ctrl-C, and exposes a localhost HTTP control API (status/start/restart/stop/logs) the admin app drives. Notable Windows handling:

  • Child PATH is rebuilt with node_modules/.bin dirs so tsx/vite resolve even when launched directly.
  • Log lines are split on \r?\n (Vite/uvicorn use LF on Windows) so output isn't stuck in a buffer.
  • Stop uses taskkill /T /F on Windows — proc.kill() would only kill the cmd.exe wrapper and orphan the tree.
const proc = spawn(cmd, args, { cwd: cwdAbs, env: childEnv, shell: process.platform === 'win32', stdio: ['ignore', 'pipe', 'pipe'] });

4. Control API + port collision

The control API binds 127.0.0.1:7474 first, then auto-increments on EADDRINUSE and persists the actual port to supervisor.json — so a second nexus dev doesn't break the admin's callbacks.

5. Config sync

sync rewrites Dockerfiles, docker.*, serve-all.mjs, and the DB name from the single nexus.config.ts — one source of truth, no stale ports. config-sync.ts fingerprints values so --check can report drift.

GraphQL @bhooai/nexus-graphql builds on graphql-js with a hand-rolled federation layer — composition, supergraph SDL, a query planner, entity joins — and subscriptions over WebSocket. No Apollo.

Code walkthrough

1. Single-subgraph gateway (the default app shape)

apps/backend builds one subgraph over users and passes it straight in:

const usersSubgraph = buildUsersSubgraph();   // sdl + resolvers
const gateway = createGateway({ subgraph: usersSubgraph });
router.post(config.graphql.path, graphqlHttpHandler({ gateway, introspection: true, context: graphContext }));

Single-subgraph mode executes directly against the subgraph's resolvers — no network hop, shared in-process context. This is the no-overhead path; federation only kicks in with >1 subgraph.

2. The users subgraph

type User @key(fields: "id") { id, email, name, roles, emailVerified, createdAt, updatedAt }
type Query { me: User, user(id: ID!): User, users(limit: Int = 50): [User!]! }
type Subscription { userCount: Int! }

3. Federation (multi-subgraph)

composeSupergraph merges subgraph SDLs into a supergraph, parseMetadata extracts @key entities, and executor builds a FetchNode DAG: it joins entities across subgraphs via _entities queries on __typename + keyFields. The current planner is deliberately a correct, naive sequential executor — parallelizing it is a documented next step.

4. Subscriptions

PubSub is in-process publish/subscribe. After registration the backend publishes USER_COUNT, and the userCount subscription streams it. SubscriptionServer serves it over /graphql/ws using the shared auth service.

Federation subset v1 supports @key/@external/@provides/@requires/@extends. @shareable, @override, and @inaccessible are documented but not enforced.

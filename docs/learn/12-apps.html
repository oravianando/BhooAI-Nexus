The Apps The four terminals — how the backend boots everything, how the frontend signs in and calls the APIs, how the admin SPA operates the platform, and how Docker packages it all.

1 · Backend (apps/backend)

src/main.ts is the whole bootstrap. Order of operations:

  1. Load config (loadConfigAuto) + logger.
  2. Connect MongoDB (required at boot) + the shared nexus_projects store.
  3. Build an AuthService shared by realtime + GraphQL.
  4. Register routes in dependency order.
  5. Construct NexusServer with the security stack.
  6. Attach realtime WS, GraphQL subscriptions, plugins, cluster.
const server = new NexusServer({
  router,
  bodyLimit: config.server.bodyLimit,
  middleware: [
    securityHeaders(), cors({ origin: true, credentials: true }),
    serveStatic(uploadsDir, { prefix: config.uploads.path }),
    bodyParser(config.server.bodyLimit),
    csrf({ trustedOrigins: trustedOrigins(config) }),
    rateLimit({ windowMs: 60_000, max: 300 }),
  ],
});
await server.listen(config.server.port, config.server.host);

2 · Frontend (apps/frontend)

App.tsx shows a landing page until a user is present, then the demo tabs: Home (GraphQL), AI Chat (SSE), Checkout (payments), Live Stream (WebRTC), Realtime Room (WS).

The lib/ folder is the API client layer:

FileRole
auth.tsCSRF + register/login/logout/refresh, in-memory access token, OAuth ?token promote.
graphql.tsGraphQL query client (POST /graphql).
ai.tsAI chat client (POST /ai/chat/completions, SSE).
payments.tsOrder create/capture/status helpers.
realtime.ts / stream.tsWS room client / WebRTC stream client.

Notable security detail in auth.ts: the access token lives in memory only (not localStorage) to reduce XSS exposure; refresh uses the HttpOnly cookie. CSRF uses the double-submit scheme — a nexus_csrf cookie plus an x-csrf-token header.

CSS pipeline

Both the frontend and admin use Tailwind CSS with the framework-owned @bhooai/nexus-postcss preset. The preset loads 6 PostCSS plugins in order:

  1. postcss-import — @import resolution
  2. postcss-nested — native CSS nesting
  3. tailwindcss — base/components/utilities + content scanning
  4. postcss-preset-env — future CSS features (stage 2)
  5. autoprefixer — vendor prefixes
  6. cssnano — minification (production only)

A theme.css design-token stylesheet provides 22 CSS custom properties (--nexus-bg, --nexus-ink, --nexus-surface, --nexus-accent, etc.) for a consistent dark theme across all Nexus apps. See the PostCSS API reference and the Frontend Styling guide.

3 · Admin (packages/nexus-admin + apps/admin)

apps/admin is a thin Vite launcher; the console lives in packages/nexus-admin/src/App.tsx (2,000+ lines). Tabs: Overview, Processes, Config JSON, Environment, Plugins, Users, Monitoring, Payments, Databases, AI Schema, Cluster, Theme Centre. It talks to the backend via src/api.ts (proxied /admin/*) and drives the supervisor control API at :7474.

4 · Docker

The Dockerfile builds backend + built frontend + built admin into one image; bin/serve-all.mjs spawns them. MongoDB/Redis/Python stay on the host (host.docker.internal). docker.ps1/docker.sh wrap build/run/logs.

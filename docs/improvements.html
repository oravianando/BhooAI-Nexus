EVOLUTION LOG

Improvements & Next Steps What changed, what is stable, and what should be hardened next.

This is the implementation and hardening log. It records improvements made over the naive approach and concrete next steps for turning the developer platform into a production platform. The current runtime uses a project-root .env, a user-owned nexus.config.ts, a gitignored runtime override file, and a Windows-safe process-tree supervisor. Each item is honest about the current seam.

A. Improvements already made during the build

Architecture

  • Scoped packages over a mega-package. 14 @bhooai/nexus-* packages so the frontend can tree-shake and each subsystem is independently testable.
  • Custom supervisor instead of concurrently/pm2. Owns the four child processes, streams prefixed colored logs, graceful Ctrl-C, and a localhost control API (:7474) the admin drives — decoupling admin from OS-specific process management (important on Windows).
  • nexus.runtime.json instead of AST patching. Admin writes overrides to a gitignored JSON file rather than rewriting nexus.config.ts with ts-morph. The typed config stays clean.
  • Single cross-service contract. contracts/ai-openapi.yaml is the source of truth for the Node↔Python boundary; both derive from it, eliminating drift.

GraphQL (no Apollo)

  • graphql core + a from-scratch federation layer. Composition, supergraph SDL, a query planner (FetchNode DAG with @key joins, @provides/@requires), and a gateway executor — all ours.
  • In-process vs distributed behind one gateway interface. A single-subgraph app pays no federation overhead; nexus add subgraph opts in. The naive sequential planner is correct before being clever.

Data (custom ODM)

  • ODM on the official mongodb driver, self-contained validators (no zod in the data layer). Full hooks, batched multi-level populate with refPath, withTransaction, auto-index creation at boot.
  • New-instance vs hydrate discipline. create() builds _isNew=true so save() inserts; hydrate() rehydrates. A real bug class caught during the build.

Security

  • CSRF on the WebSocket upgrade (double-submit via query/`Sec-WebSocket-Protocol`) — a gap most frameworks leave open.
  • Access tokens in memory, refresh in HttpOnly cookies on the frontend — reduces XSS token theft vs. localStorage.
  • Double-submit CSRF with origin check gated on a non-empty trustedOrigins (a single-origin deploy isn't accidentally locked out).

Plugins

  • Real isolation via worker_threads for sandboxed plugins (heap/event-loop isolation, crash can't take down the host) with a capability policy (fs path-allowlist, net host-allowlist, method caps) + heartbeat watchdog. Documented as not a cryptographic sandbox.

AI

  • One OpenAI-compatible provider for both OpenAI and Ollama (same API shape) — half the code. The server re-emits SSE with a provider tag and strips it before forwarding upstream.

Payments / Crypto

  • Hand-rolled DER/ASN.1 encoder for CSR (~400 lines) instead of node-forge — node:crypto creates keys/certs but not CSRs.
  • Injectable HttpTransport on every payment provider — tests inject mocks, no live-gateway keys; the provider abstraction is identical across all five gateways.

B. Suggested next steps (production hardening)

Federation

  1. Parallel query planner. Replace sequential entity-join passes with a parallel FetchNode scheduler (concurrent independent subgraphs, batched _entities).
  2. Federation directive coverage. Implement @shareable arbitration, @override, @inaccessible enforcement.
  3. Subscription federation — a routing layer for subscriptions across subgraphs.
  4. Distributed mode hot-swap. Ship SDL polling + atomic schema swap for multi-instance deploys.

ODM

  1. Query plan caching / DataLoader. Dedupe within a resolver tree to cut N+1 to 1.
  2. Change streams for real-time cache invalidation and subscription fan-out from Mongo.
  3. Lean cursors / streaming aggregation to avoid materializing large result sets.
  4. Schema migrations — a runner for renames/drops (auto-index handles additive).

Realtime / WebRTC

  1. Producer discovery API on the SFU. Add a getProducers action so late joiners consume existing producers without waiting for a re-announce.
  2. Room/transport lifecycle hardening — server-driven consumer close, ICE restart on failures.
  3. Horizontal-scale pub/sub — verify Redis fanout under multi-instance + sticky-session LB.

Security

  1. Redis-backed rate limit + session store so limits survive restarts and apply across instances.
  2. Access-token denylist (Redis) for instant logout across instances.
  3. Security headers audit — add a CSP builder and Permissions-Policy.
  4. Plugin sandbox escape audit — document (and add) child-process / OCI isolation for truly untrusted plugins.

AI

  1. Token-usage accounting + cost guardrails — per-user/tenant billing and per-key quotas.
  2. Streaming backpressure — flow control so a slow client doesn't balloon server memory.
  3. Provider failover — per-request OpenAI → Ollama on upstream errors.

Payments

  1. Idempotency keys on create-order to make retries safe.
  2. Webhook replay protection (timestamp + event-id dedup via Redis).
  3. Full PayU/Skrill/Payoneer — raw-HTTP completion for capture/refund/verify.

Frontend / Admin

  1. Route-level code-splitting — lazy-load the mediasoup-client-heavy LiveStream route.
  2. OAuth callback UX — promote ?token= to a same-page postMessage or short-lived exchange code.
  3. Admin live plugin install/uninstall — wire the UI to the registry's load/unload at runtime.

Ops / Release

  1. CI matrix — Win + Linux running vitest + pytest + Playwright e2e. done
  2. nexus init templates — real template files; generated backend is runnable, not a placeholder. done
  3. OpenTelemetry tracing — emit spans to OTLP for distributed traces in the admin monitoring pane.
  4. Container build — a Dockerfile per terminal + compose for Mongo/Redis + the four services.

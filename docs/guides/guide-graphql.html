GUIDE

GraphQL API Build a subgraph, mount it on a gateway, expose POST /graphql, add subscriptions over WebSocket, and federate multiple subgraphs — all on @bhooai/nexus-graphql (graphql-js + a hand-rolled federation layer, no Apollo).

The flow

defineSubgraph({typeDefs, resolvers})  ──>  createGateway({subgraph})  ──>  graphqlHttpHandler on POST /graphql
                                              │
                                              └─> SubscriptionServer on ws://host/graphql/ws   (graphql-transport-ws)

1. Define a subgraph

defineSubgraph takes SDL typeDefs (with federation @key directives) and resolvers. It auto-wires _service { sdl } and _entities, prepends the federation directive definitions + @link, and parses @key (single + composite):

import { defineSubgraph, createGateway, graphqlHttpHandler, PubSub, SubscriptionServer } from '@bhooai/nexus-graphql';

const todoSubgraph = defineSubgraph({
  typeDefs: `
    type Todo @key(fields: "id") {
      id: ID!
      title: String!
      done: Boolean!
      ownerId: ID!
    }
    type Query {
      todos(limit: Int = 50): [Todo!]!
      todo(id: ID!): Todo
    }
    type Mutation {
      addTodo(title: String!): Todo!
      toggleTodo(id: ID!): Todo
    }
    type Subscription {
      todoAdded: Todo!
    }
  `,
  resolvers: {
    Query: {
      todos:   (_p, { limit }) => Todo.find().limit(limit).lean(),
      todo:    (_p, { id })     => Todo.findById(id).lean(),
    },
    Mutation: {
      addTodo:   (_p, { title }, ctx) => Todo.create([{ title, done: false, ownerId: ctx.user.id }]),
      toggleTodo: async (_p, { id }) => {
        const t = await Todo.findById(id);
        t.done = !t.done; await t.save();
        return t.toObject();
      },
    },
    Subscription: {
      todoAdded: { subscribe: () => pubsub.asyncIterator('TODO_ADDED') },
    },
    Todo: {
      __resolveReference: (rep) => Todo.findById(rep.id).lean(),   // federation entity join
    },
  },
});
@key(fields: "id") The @key directive marks Todo as a federation entity whose identity is the id field. Other subgraphs can reference Todo via @extends and the gateway will join through __resolveReference.

2. Create the gateway

Single-subgraph mode executes directly against the subgraph's resolvers — no network hop, shared in-process context. This is the no-overhead path:

const gateway = createGateway({ subgraph: todoSubgraph });

3. Mount the HTTP handler — POST /graphql

graphqlHttpHandler handles POST /graphql with a JSON body of { query, variables, operationName }. The context factory receives the request context and returns the GraphQL context:

router.post(config.graphql.path, graphqlHttpHandler({
  gateway,
  introspection: config.graphql.introspection,   // gate introspection in prod
  context: async (ctx) => ({
    request: ctx,
    user: ctx.state.user,          // populated by authToken middleware
    pubsub,
  }),
}));

4. Subscriptions over WebSocket

SubscriptionServer speaks the graphql-transport-ws protocol on ws://host/graphql/ws. Auth uses the connection_init payload — send the JWT as token; the auth service verifies it once on connect:

const pubsub = new PubSub();

const subs = new SubscriptionServer({
  httpServer: server.httpServer,
  gateway,
  path: '/graphql/ws',
  authService,
  context: (_init, user) => ({ user, pubsub }),
});

// publish from anywhere in the app:
pubsub.publish('TODO_ADDED', { todoAdded: newTodo });

Browser subscription client

import { createClient } from 'graphql-transport-ws';

const ws = createClient({
  url: `ws://${location.host}/graphql/ws`,
  connectionParams: () => ({ token: localStorage.getItem('accessToken') }),
});

ws.subscribe(
  { query: 'subscription { todoAdded { id title done } }' },
  {
    next: ({ data }) => console.log('new todo', data.todoAdded),
    error: (e) => console.error(e),
    complete: () => console.log('closed'),
  },
);
contextValue vs context gateway.subscribe({ document, contextValue }) needs a parsed DocumentNode (parse(query)) and the parameter is named contextValue. HTTP execute uses context. They differ — don't mix them up.

5. Multi-subgraph federation

With more than one subgraph, switch to createFederatedGateway. composeSupergraph merges the SDLs, parseMetadata extracts @key entities, and the executor builds a FetchNode DAG that joins entities via _entities queries on __typename + keyFields:

const usersSubgraph = defineSubgraph({ typeDefs: usersSDL,  resolvers: usersResolvers  });
const todosSubgraph = defineSubgraph({ typeDefs: todosSDL,  resolvers: todosResolvers });

const gateway = createFederatedGateway({ subgraphs: [usersSubgraph, todosSubgraph] });

router.post('/graphql', graphqlHttpHandler({ gateway, introspection: true, context }));
When to federate Use the federated gateway only with >1 subgraph. The single-subgraph path skips composition and planning entirely and runs execute() directly against the public schema — same DX, zero overhead.

6. Browser — fetch POST /graphql

Queries and mutations are plain POSTs. Send the CSRF header (the endpoint is a POST) and the JWT as a Bearer token:

async function gql(query, variables = {}) {
  const res = await fetch('/graphql', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-csrf-token': csrfToken,
      'Authorization': `Bearer ${accessToken}`,
    },
    body: JSON.stringify({ query, variables }),
  });
  const { data, errors } = await res.json();
  if (errors) throw new Error(errors[0].message);
  return data;
}

const data = await gql(
  `mutation($title:String!){ addTodo(title:$title){ id title done } }`,
  { title: 'Ship the gateway' },
);

7. Introspection gating

Introspection is controlled by config.graphql.introspection. Enable it in dev so tools like the GraphQL playground and Postman auto-complete the schema; disable it in production to avoid leaking your API surface:

graphql: {
  path: '/graphql',
  introspection: process.env.NODE_ENV !== 'production',
  playground:   process.env.NODE_ENV !== 'production',
}
Federation subset (v1) Supported: @key (single + composite), @external, @requires, @provides, @extends, _entities, _service { sdl }. @shareable arbitration, @override, and @inaccessible enforcement are documented but not enforced yet. Don't rely on them for correctness.

GUIDE

Login & Auth Flow CSRF, JWT access/refresh tokens, cookies, RBAC, and optional Google OAuth — the complete end-to-end flow with server- and browser-side code.

Nexus auth is one cohesive unit: CSRF → CORS → security headers → rate limit → body parse → router. This guide walks through every endpoint a browser hits, shows the exact request/response shapes, and explains how to protect your own routes.

The full flow at a glance

┌────────────┐   GET /csrf-token     ┌──────────────┐
│  Browser   │ ───────────────────▶ │   Backend    │
│            │ ◀── cookie + token ─ │ (CSRF + JWT) │
│            │                      │              │
│            │   POST /auth/login    │              │
│            │   x-csrf-token: ...   │              │
│            │ ───────────────────▶ │              │
│            │ ◀── user + tokens ─── │              │
│            │   + HttpOnly cookies   │              │
│            │                      │              │
│            │   GET /auth/me        │              │
│            │   Authorization: Bearer ...          │
│            │ ───────────────────▶ │              │
│            │ ◀── { user } ─────── │              │
└────────────┘                      └──────────────┘

1. CSRF token flow

CSRF uses the double-submit cookie pattern. Safe methods (GET/HEAD/OPTIONS/TRACE) get a fresh nexus_csrf cookie and expose the token in the response body. Unsafe methods must send it back in the x-csrf-token header.

// Step 1 — get a CSRF token (also sets the nexus_csrf cookie)
GET /csrf-token
Origin: http://localhost:3000

// 200 response
{
  "token": "HcdAC3ODLYNqXNv4XA9UjScsgPbEAovG"
}
// Set-Cookie: nexus_csrf=HcdAC3ODLYNqXNv4XA9UjScsgPbEAovG; HttpOnly; ...
// Step 2 — every POST/PUT/PATCH/DELETE must echo the token
POST /auth/login
Origin: http://localhost:3000
Content-Type: application/json
x-csrf-token: HcdAC3ODLYNqXNv4XA9UjScsgPbEAovG

{ "email": "demo@nexus.local", "password": "password" }
CSRF gotchas With a non-empty trustedOrigins, every unsafe request must carry an Origin header that exactly matches a trusted origin (including the port) and a matching x-csrf-token. The WebSocket upgrade verifies the same token via Sec-WebSocket-Protocol. Loopback origins are trusted regardless of port; external origins match strictly.

2. Register

POST /auth/register creates a user and returns the auth bundle. The very first registered user is bootstrapped as admin; everyone after gets user.

POST /auth/register
Origin: http://localhost:3000
Content-Type: application/json
x-csrf-token: <token>

{
  "email": "founder@myapp.com",
  "password": "supersecret-8-chars",
  "name": "Founder"
}
// 200 response
{
  "user": {
    "_id": "6823...",
    "email": "founder@myapp.com",
    "name": "Founder",
    "roles": ["admin"]       // first user → admin
  },
  "accessToken": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiI...",
  "refreshToken": "eyJhbGciOiJIUzI1NiJ9.eyJzaWQiOiI..."
}
// Set-Cookie: nexus_sid=<accessToken>; HttpOnly; SameSite=Lax
// Set-Cookie: nexus_rid=<refreshToken>; HttpOnly; SameSite=Lax
Password rules Passwords are bcrypt-hashed via hashPassword / verifyPassword. The minimum length is 8 characters; the ValidationError is thrown otherwise.

3. Login

POST /auth/login
Origin: http://localhost:3000
Content-Type: application/json
x-csrf-token: <token>

{ "email": "founder@myapp.com", "password": "supersecret-8-chars" }
// 200 response — same shape as register
{
  "user":  { "_id": "...", "email": "...", "roles": ["admin"] },
  "accessToken":  "eyJ...",
  "refreshToken": "eyJ..."
}
// Set-Cookie: nexus_sid=...; nexus_rid=...

Invalid credentials return 401 with a generic message ("Invalid email or password") so email enumeration is not possible.

4. Get current user

GET /auth/me
Authorization: Bearer eyJ...        // access token

// 200 response
{ "user": { "_id": "...", "email": "...", "roles": ["admin"] } }

The authToken middleware reads the Bearer header (or the nexus_sid cookie when allowCookie: true), verifies it via AuthService.verifyAccessToken, and populates ctx.state.user = { id, roles, sid }. requireAuth() then ensures a user is present.

5. Refresh

Access tokens are short-lived (default 15m). Refresh tokens rotate on every use, and reuse of an old refresh token revokes the whole session family (reuse detection).

POST /auth/refresh
Content-Type: application/json
x-csrf-token: <token>

{ "refreshToken": "eyJ..." }   // or omit body — read from nexus_rid cookie

// 200 response — fresh pair
{ "accessToken": "eyJ.new...", "refreshToken": "eyJ.new..." }
// Set-Cookie: nexus_sid=...; nexus_rid=...  (rotated)
// Server-side rotation + reuse detection (AuthService.refresh)
if (session.currentJti && payload.jti && session.currentJti !== payload.jti) {
  await this.sessions.destroyFamily(session.familyId);
  throw new AuthenticationError('Refresh token reuse detected; session revoked');
}
JWT kinds are segregated jwt.ts signs tokens with a kind discriminator (access vs refresh). An access token can never be used to refresh, and a refresh token can never be used as a Bearer for /auth/me.

6. Logout

POST /auth/logout
x-csrf-token: <token>
Authorization: Bearer eyJ...   // optional — never 401s on logout

// 200 response
{ "ok": true }
// Set-Cookie: nexus_sid=; Max-Age=0   (cleared)
// Set-Cookie: nexus_rid=; Max-Age=0   (cleared)

7. Protecting your own routes

Route-level middleware is the third argument to router.<method>(). Chain authToken for auth + requireRole for RBAC.

import { authToken, requireRole, requireAuth } from '@bhooai/nexus-auth';

// Any authenticated user
router.get('/me', handler, [
  authToken(authService, { cookieName: config.auth.cookieName, allowCookie: true, required: true }),
  requireAuth(),
]);

// Admin only
router.get('/admin/users', handler, [
  authToken(authService, { cookieName: config.auth.cookieName, allowCookie: true }),
  requireRole('admin'),
]);
Signature authToken(service: AuthService, options: AuthTokenOptions) — the first argument is the AuthService instance; options are the second. allowCookie: true lets the middleware fall back to the nexus_sid cookie when the Authorization header is absent.

8. Google OAuth (optional)

OAuth is wired only when config.auth.google.clientId is set. The flow is PKCE + state.

// nexus.config.ts
auth: {
  google: {
    clientId: '...apps.googleusercontent.com',
    clientSecret: '...',
    callbackPath: '/auth/google/callback',
    scope: 'openid email profile',
  },
}
// Browser flow
1. GET /auth/google
   → redirects to accounts.google.com with state + PKCE verifier
2. User consents on Google
3. Google redirects back to /auth/google/callback?code=...&state=...
4. Backend exchanges code → tokens → fetches profile → upserts user
5. Response: { user, accessToken } + sets nexus_sid / nexus_rid cookies
// Server-side (authRoutes.ts)
router.get('/auth/google', async (ctx) => {
  const state = generateState();
  const verifier = generatePkceVerifier();
  await oauthState.set(state, { provider: 'google', verifier }, 5 * 60_000);
  ctx.redirect(buildGoogleAuthUrl(google, { state, verifier }));
});

router.get(config.auth.google.callbackPath, async (ctx) => {
  const { code, state } = ctx.query as { code?: string; state?: string };
  const data = await oauthState.consume(state);
  const tokens = await exchangeGoogleCode(code, google, data.verifier);
  const profile = await fetchGoogleProfile(tokens.accessToken);
  const user = await upsertOAuthUser({ provider: 'google', providerUserId: profile.providerUserId, email: profile.email, name: profile.name });
  const pair = await service.login({ userId: String(user._id), roles: user.roles });
  setAuthCookies(ctx, pair, { accessTokenName: config.auth.cookieName, refreshTokenName: config.auth.refreshCookieName });
  ctx.json({ user: publicUser(user), accessToken: pair.accessToken });
});

9. Browser fetch example — full login flow

// lib/auth.ts — the frontend pattern (simplified from apps/frontend)
let csrfToken = '';
let accessToken = '';   // lives in memory only — NOT localStorage
let currentUser = null;

async function refreshCsrf() {
  if (csrfToken) return;
  const r = await fetch('/csrf-token', { credentials: 'include' });
  csrfToken = (await r.json()).token;
}

function csrfHeaders() {
  return { 'x-csrf-token': csrfToken };
}
function authHeaders() {
  return accessToken ? { authorization: 'Bearer ' + accessToken } : {};
}

async function postJson(path, body) {
  await refreshCsrf();
  const r = await fetch(path, {
    method: 'POST', credentials: 'include',
    headers: { 'content-type': 'application/json', ...csrfHeaders(), ...authHeaders() },
    body: JSON.stringify(body),
  });
  if (!r.ok) throw new Error((await r.json()).error?.message ?? r.statusText);
  return r.json();
}

// Register → first user becomes admin
const res = await postJson('/auth/register', {
  email: 'founder@myapp.com', password: 'supersecret-8-chars', name: 'Founder',
});
accessToken = res.accessToken;
currentUser = res.user;
console.log('logged in as', currentUser.email, currentUser.roles);

// Call a protected endpoint
const me = await fetch('/auth/me', {
  headers: { authorization: 'Bearer ' + accessToken },
  credentials: 'include',
}).then(r => r.json());
console.log(me.user);

// Refresh when the access token expires
async function maybeRefresh() {
  try {
    const fresh = await postJson('/auth/refresh', {});
    accessToken = fresh.accessToken;
  } catch { currentUser = null; }
}

// Logout
async function logout() {
  await postJson('/auth/logout', {});
  accessToken = ''; currentUser = null;
}
Why the token is in memory The access token lives in memory only (not localStorage) to reduce XSS exposure. Refresh uses the HttpOnly nexus_rid cookie, which JavaScript cannot read.

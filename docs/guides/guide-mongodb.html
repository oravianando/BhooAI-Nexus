GUIDE

MongoDB CRUD End-to-end ODM operations with @bhooai/nexus-data — connect, schema, model, create, read, update, delete, populate, transactions, and $jsonSchema validators. A from-scratch ODM on the official mongodb driver (no mongoose).

1. Connect

connect(uri) opens the single shared connection and registers it on the ConnectionManager. The underlying MongoClient is lazy — it connects on first db access:

import { connect, getConnection, model, Schema, transaction } from '@bhooai/nexus-data';

await connect(config.db.uri, {
  name: 'myapp',
  autoIndex: true,
});
await getConnection().db;          // forces the driver to connect

2. Schema definition

Fields declare type, required, index/unique, default, immutable, and ref (or refPath for dynamic refs). Schema-level options add timestamps, collection, and strict:

const postSchema = new Schema({
  title:    { type: String, required: true, trim: true, maxlength: 200 },
  slug:     { type: String, required: true, unique: true, immutable: true },
  body:     { type: String, required: true },
  author:   { type: 'ObjectId', ref: 'User', required: true, index: true },
  tags:     { type: [String], default: () => [] },
  views:    { type: Number, default: 0, min: 0, immutable: true },
  status:   { type: String, enum: ['draft', 'live', 'archived'], default: 'draft' },
  publishedAt: { type: Date, default: null },
}, { timestamps: true, collection: 'posts', strict: true });
immutable An immutable field can be set on create but never changed afterwards. Use it for slug, author, or audit fields that must not drift.

3. Model creation

const Post = model<PostDoc>('Post', postSchema);
// indexes are created on connect (autoIndex: true)

4. Create

Model.create builds new instances (_isNew = true), applies defaults, validates, then inserts:

const [post] = await Post.create([{
  title: 'Hello Nexus',
  slug:  'hello-nexus',
  body:  'First post.',
  author: userId,
  status: 'draft',
}]);
// post._id is now set; post.createdAt / updatedAt auto-populated

5. Read — find chain

A fluent query builder: find, where, operators like gt, sort, limit, populate, lean:

const top = await Post
  .find({ status: 'live' })
  .where('views').gt(100)
  .sort('-publishedAt')
  .limit(10)
  .populate('author', 'name email')   // batched, no N+1
  .lean();                                // plain objects, no proxies

Read one

const byId    = await Post.findById(id);              // 24-char hex → ObjectId
const bySlug  = await Post.findOne({ slug: 'hello-nexus' });

6. Update

await Post.updateOne(
  { _id: post._id },
  { $set: { status: 'live', publishedAt: new Date() } },
);

const updated = await Post.findByIdAndUpdate(
  post._id,
  { $inc: { views: 1 } },                       // immutable: views stays a Number
  { returnDocument: 'after' },
);

7. Delete

await Post.deleteOne({ _id: post._id });
await Post.findByIdAndDelete(post._id);

8. Populate (joins)

Populate is batched — one extra query per relation regardless of how many docs reference it. Use a field projection string to limit the joined fields:

const live = await Post.find({ status: 'live' }).populate('author', 'name email').lean();
// live[0].author === { _id, name, email }   (not the full user doc)
Always lean() for serialization Serialize via lean() (queries) or toObject() (instances). Spreading a DocumentInstance proxy leaks internal fields including a circular _model.

9. Transactions

transaction(fn) wraps the callback in a driver session.withTransaction. Pass the session into each operation via the options. On throw the transaction aborts automatically:

await transaction(async (session) => {
  const [p] = await Post.create([{ title, slug, body, author: uid }], { session });
  await User.updateOne({ _id: uid }, { $inc: { postCount: 1 } }, { session });
  return p;
});

10. $jsonSchema validators

MongoDB collection validators enforce shape at the database layer — a backstop for direct driver writes. Define them with createCollection and a $jsonSchema validator:

await db.createCollection('posts', {
  validator: {
    $jsonSchema: {
      bsonType: 'object',
      required: ['title', 'slug', 'author', 'status'],
      properties: {
        title:    { bsonType: 'string', maxLength: 200 },
        slug:     { bsonType: 'string', pattern: '^[a-z0-9-]+$' },
        author:   { bsonType: 'objectId' },
        views:    { bsonType: 'int', minimum: 0 },
        status:   { enum: ['draft', 'live', 'archived'] },
        publishedAt: { bsonType: ['date', 'null'] },
      },
    },
  },
  validationLevel: 'strict',
  validationAction: 'error',
});
Two layers The ODM schema is the front gate (app-level errors, friendly messages). The $jsonSchema validator is the back gate (any direct mongo shell or migration write is also constrained). Use both.

11. Count

const total    = await Post.countDocuments({ status: 'live' });
const drafts   = await Post.countDocuments({ status: 'draft' });
const byAuthor = await Post.countDocuments({ author: uid });

12. Complete example — Post model with CRUD routes

Tie it together: schema, model, and a small router covering list / get / create / update / delete:

// postModel.ts
const postSchema = new Schema({
  title:       { type: String, required: true, maxlength: 200 },
  slug:        { type: String, required: true, unique: true, immutable: true },
  body:        { type: String, required: true },
  author:      { type: 'ObjectId', ref: 'User', required: true, index: true },
  tags:        { type: [String], default: () => [] },
  views:       { type: Number, default: 0, min: 0, immutable: true },
  status:      { type: String, enum: ['draft', 'live', 'archived'], default: 'draft' },
  publishedAt: { type: Date, default: null },
}, { timestamps: true, collection: 'posts' });

postSchema.pre('save', function () {
  if (this.isModified('title') && !this.slug) {
    this.slug = this.title.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '');
  }
});

export const Post = model('Post', postSchema);

// postRoutes.ts
router.get('/posts', async (ctx) => {
  const { status = 'live', limit = 20, page = 1 } = ctx.query;
  const posts = await Post.find({ status })
    .sort('-publishedAt')
    .skip((page - 1) * limit)
    .limit(+limit)
    .populate('author', 'name email')
    .lean();
  ctx.body = { posts, total: await Post.countDocuments({ status }) };
});

router.get('/posts/:id', async (ctx) => {
  const post = await Post.findById(ctx.params.id).populate('author').lean();
  if (!post) throw new NotFoundError('post');
  ctx.body = { post };
});

router.post('/posts', requireAuth(), async (ctx) => {
  const [post] = await Post.create([{ ...ctx.request.body, author: ctx.state.user.id }]);
  ctx.status = 201; ctx.body = { post: post.toObject() };
});

router.patch('/posts/:id', requireAuth(), async (ctx) => {
  const post = await Post.findByIdAndUpdate(ctx.params.id,
    { $set: ctx.request.body }, { returnDocument: 'after' }).lean();
  ctx.body = { post };
});

router.delete('/posts/:id', requireAuth(), requireRole('admin'), async (ctx) => {
  await Post.findByIdAndDelete(ctx.params.id);
  ctx.status = 204;
});
create() vs hydrate() create() marks documents _isNew = true so save() inserts. hydrate() marks them persisted so save() updates. Never hydrate when you mean create — it will silently run an update with an empty filter.

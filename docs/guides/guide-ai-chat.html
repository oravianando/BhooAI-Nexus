GUIDE

AI Chat Streaming Stream AI chat completions end to end — Browser → Node proxy (CSRF) → Python FastAPI → upstream provider — with Server-Sent Events re-emitted at every hop.

The streaming flow

Browser ──> Node backend (:4000) ──> Python FastAPI (:8000) ──> OpenAI / Together / Ollama
        fetch + ReadableStream     POST /ai/chat/completions    providers/base.py
        parse SSE chunks           re-emits SSE                  StreamingResponse

1. AI server setup — Python FastAPI

The Python AI gateway lives in apps/ai-server/main.py and listens on port 8000. One Provider class (in providers/base.py) covers every OpenAI-compatible backend (OpenAI, Together AI, Ollama, Groq, …). Start it with:

# from the repo root
cd apps/ai-server
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000 --reload

Verify it is alive:

curl http://localhost:8000/health
# {"status":"ok","provider":"auto"}
OpenAI-compatible Every supported provider speaks the OpenAI Chat Completions shape, so the Python side routes purely on base_url + auth header. The provider field in the request body is stripped before forwarding upstream.

2. Backend proxy — POST /ai/chat/completions

The Node backend never lets the browser call Python directly. apps/backend/src/modules/ai/aiProxy.ts exposes POST /ai/chat/completions, is CSRF protected, re-emits the SSE stream so CSRF + auth stay in Node, and re-injects the provider tag into each chunk:

router.post('/ai/chat/completions',
  authToken(authService, { required: false }),
  csrf(),                        // double-submit CSRF
  aiChatHandler);                // pipes upstream SSE straight through

3. Provider configuration — nexus.config.ts

20 providers are pre-configured in nexus.config.ts under ai.providers. Each entry has enabled, baseUrl, and an env var name for its API key:

ai: {
  serverUrl: 'http://localhost:8000',
  providers: {
    openai:   { enabled: true,  baseUrl: 'https://api.openai.com/v1',   apiKeyEnv: 'NEXUS_AI_OPENAI_API_KEY' },
    together: { enabled: true,  baseUrl: 'https://api.together.xyz/v1', apiKeyEnv: 'NEXUS_AI_TOGETHER_API_KEY' },
    ollama:   { enabled: true,  baseUrl: 'http://localhost:11434/v1',    apiKeyEnv: null },
    groq:     { enabled: false, baseUrl: 'https://api.groq.com/openai/v1', apiKeyEnv: 'NEXUS_AI_GROQ_API_KEY' },
    // ... 16 more pre-configured providers
  },
}

API keys in .env

Keys follow the NEXUS_AI_<PROVIDER>_API_KEY convention. They are read by the Python server, never by the browser:

# .env  (Python ai-server reads these)
NEXUS_AI_OPENAI_API_KEY=sk-...
NEXUS_AI_TOGETHER_API_KEY=...
NEXUS_AI_GROQ_API_KEY=...
# Ollama needs NO key — it runs locally

4. Admin AI Providers tab

The admin console exposes an AI Providers tab where you can:

  • enable / disable any of the 20 pre-configured providers,
  • set or rotate API keys (stored encrypted, surfaced to Python only),
  • add a custom provider — name, base URL, key env var — without editing code.
No restart needed Provider toggles write to nexus.runtime.json; the Python server hot-reloads its settings on the next request via settings.py.

5. Together AI direct SDK routing

For provider: "together" the Node backend bypasses Python entirely and calls the Together AI SDK directly. This removes one hop for the most common production path:

if (provider === 'together' && config.ai.directSdk.together) {
  return togetherSdk.chatStream(body);   // browser → Node → Together (no Python)
}
// every other provider → Node proxy → Python → upstream

6. Ollama local — no API key

Set provider: "ollama" to hit a local Ollama daemon. No key is required; the base URL defaults to http://localhost:11434/v1. Great for offline dev and CI:

{
  "model": "llama3.1:8b",
  "provider": "ollama",
  "messages": [{ "role": "user", "content": "Hello, local LLM!" }],
  "stream": true
}

7. Browser streaming — full chat example

The browser uses fetch + a ReadableStream reader to parse SSE chunks as they arrive. First fetch a CSRF token, then POST to the proxy:

// 1. get CSRF token
const csrfRes = await fetch('/csrf-token');
const { token } = await csrfRes.json();

// 2. POST + stream the response
const res = await fetch('/ai/chat/completions', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-csrf-token': token,
  },
  body: JSON.stringify({
    model: 'meta-llama/Llama-3.3-70B-Instruct-Turbo',
    provider: 'together',
    messages: [{ role: 'user', content: 'Explain SSE in one line.' }],
    stream: true,
  }),
});

// 3. read SSE chunks from the ReadableStream
const reader = res.body.getReader();
const decoder = new TextDecoder();
let buffer = '';
const out = document.getElementById('chat-out');

while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });

  // SSE events are separated by blank lines
  const parts = buffer.split('\n\n');
  buffer = parts.pop();              // keep the partial tail

  for (const evt of parts) {
    for (const line of evt.split('\n')) {
      if (!line.startsWith('data: ')) continue;
      const data = line.slice(6);
      if (data === '[DONE]') continue;
      const json = JSON.parse(data);

      // error event from the proxy
      if (json.event === 'error') {
        out.textContent += '\n[error] ' + (json.message || json.error);
        continue;
      }

      const delta = json.choices?.[0]?.delta?.content || '';
      out.textContent += delta;      // append token-by-token
    }
  }
}
Why a buffer? A single read() can return a partial SSE event (cut mid-line). Always split on \n\n, keep the trailing partial in buffer, and only parse complete events.

8. Error handling

The proxy emits an SSE error event when upstream fails — the stream stays open so the browser can surface the message rather than seeing a blank 502:

data: {"event":"error","message":"provider timeout (30s)","status":504}

data: [DONE]

Detect it in the parser (see the json.event === 'error' branch above) and show it inline. Common cases:

SymptomCauseFix
event: error · 401Missing/invalid API keySet NEXUS_AI_<PROVIDER>_API_KEY in .env, restart Python
event: error · 429Rate limited upstreamRetry with backoff; lower maxTokens
event: error · timeoutUpstream > 30sRaise ai.timeoutMs in config or pick a faster model
Invalid CSRF tokenToken rotated / missingRe-GET /csrf-token before the POST
Empty stream, no chunksPython server downCheck http://localhost:8000/health
CSRF rotates Every safe-method request (GET) issues a fresh nexus_csrf cookie. Fetch the CSRF token immediately before the streaming POST; do not cache it across other requests.
Never call Python from the browser The Python server has no CSRF, CORS, or auth middleware — it trusts the Node backend. Exposing port 8000 directly to the web bypasses every security control.

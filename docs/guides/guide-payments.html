Payments Integration A gateway-agnostic PaymentProvider interface, five gateways, signature-verified webhooks, and the browser hosted-checkout flow — with a working Razorpay sandbox example.

@bhooai/nexus-payments gives you one PaymentProvider interface across Razorpay, PayPal, PayU, Skrill, and Payoneer. The scaffold already wires order/capture/status routes + a signature-verified webhook router. This guide shows the full checkout flow.

1. Config in nexus.config.ts

The payments section sets the webhook path and default currency. Provider credentials live in .env, not the config file.

// nexus.config.ts
payments: {
  webhookPath: '/payments/webhook/:provider',
  currency: 'INR',
  // Per-provider keys come from .env (NEXUS_PAYMENTS_*). The framework
  // default does NOT include provider blocks — they auto-activate on keys.
}

2. Provider keys in .env

Providers auto-enable when their keys are present (or when enabled: true is set in config). You don't need to touch code to turn a gateway on — just add the env vars.

# .env — Razorpay (sandbox test keys)
NEXUS_PAYMENTS_RAZORPAY_KEY_ID=rzp_test_1DP5XXXXXXXX
NEXUS_PAYMENTS_RAZORPAY_KEY_SECRET=xxxxxxxxxxxxxxxxxxxx

# PayPal (optional)
NEXUS_PAYMENTS_PAYPAL_CLIENT_ID=AeA1...
NEXUS_PAYMENTS_PAYPAL_CLIENT_SECRET=ELB1...
NEXUS_PAYMENTS_PAYPAL_SANDBOX=true
Compound env keys NEXUS_PAYMENTS_RAZORPAY_KEY_ID maps to payments.razorpay.keyId — the KEY_ID pair collapses into a single keyId field (not key.id). The env loader has a known list of these compound segments. 
// How a provider activates (createPayments)
const active = (cfg, keys) =>
  cfg?.enabled ?? keys.every((k) => typeof cfg[k] === 'string' && cfg[k].length > 0);

if (active(config.razorpay, ['keyId', 'keySecret'])) {
  providers.set('razorpay', new RazorpayProvider(config.razorpay));
}

3. createPayments(config.payments)

The factory builds a PaymentsService with a providers map keyed by name. The scaffold already calls it in main.ts:

// apps/backend/src/main.ts (already generated)
const payments = createPayments(config.payments);

const webhookRouter = payments.webhookRouter((ev) => {
  log.info('payment webhook event', { provider: ev.provider, event: ev.event, verified: ev.verified });
  if (ev.provider && ev.event) {
    recordTransaction(ev.provider, ev).catch((err) => log.warn('failed to record payment transaction', { msg: err.message }));
  }
});
if (config.payments.webhookPath) {
  router.post(config.payments.webhookPath, webhookRouter.handler);
}
registerPaymentRoutes(router, config, payments, authService);

4. Create order

The browser-facing order route is auth-guarded. Amounts are in major units (e.g. 99.50); Razorpay converts to paise internally via toMinor.

POST /payments/order
Authorization: Bearer <accessToken>
Content-Type: application/json
x-csrf-token: <token>
Origin: http://localhost:3000

{
  "provider": "razorpay",
  "amount": 99.50,
  "currency": "INR",
  "reference": "order_2026_001",
  "description": "Pro plan — monthly"
}
// 200 response
{
  "provider": "razorpay",
  "order": {
    "orderId": "order_Nktp...",
    "paymentUrl": "https://api.razorpay.com/v1/checkout/embedded?...",
    "amount": 9950,
    "currency": "INR",
    "status": "created"
  }
}
Minor units toMinor converts major → minor based on ISO 4217. INR/USD/EUR multiply by 100 (paise/cents); JPY/KRW are zero-dp (no multiplier); KWD/BHD multiply by 1000 (three decimal places).

5. Hosted checkout — redirect to paymentUrl

For hosted-checkout providers (Razorpay, PayU, Skrill, Payoneer), the order.paymentUrl is where the customer completes payment. Redirect the browser there; the gateway redirects back to your returnUrl (or cancelUrl on cancellation).

// Browser — after creating the order
const { order } = await fetch('/payments/order', {
  method: 'POST', credentials: 'include',
  headers: { 'content-type': 'application/json', ...csrfHeaders(), ...authHeaders() },
  body: JSON.stringify({ provider: 'razorpay', amount: 99.50, currency: 'INR' }),
}).then(r => r.json());

// Redirect to the hosted checkout page
window.location.href = order.paymentUrl;

6. Webhook — signature verified, no auth/CSRF

Webhooks are mounted separately from the auth-guarded checkout routes. They have no auth/CSRF — security comes from the signature. The WebhookRouter verifies the raw body (kept on ctx.state.__rawBody) against the provider signature, rejects with 401 on mismatch, and ACKs 200 so the gateway doesn't retry.

POST /payments/webhook/razorpay
X-Razorpay-Signature: <hmac-sha256 hex>
Content-Type: application/json

{ "entity": "payment", "id": "pay_...", ... }
// Server-side verification (WebhookRouter)
const event = await provider.verifyWebhook({ rawBody, headers, params: ctx.params });
if (!event.verified) {
  ctx.json({ error: 'signature verification failed' }, 401);
  return;
}
try { await this.onEvent(event); }
catch { ctx.json({ ok: false }, 200); return; }
ctx.json({ ok: true }, 200);
Webhook = source of truth Never trust a client-side "payment succeeded" callback. The webhook is the authoritative event. Persist every verified webhook as a transaction (the scaffold does this via recordTransaction); the admin dashboard reads from that store.

7. Capture an authorized order

For providers that separate authorization from capture (e.g. Razorpay for card flows that authorize but don't auto-capture), call capture after the webhook confirms payment.

POST /payments/order/:id/capture
Authorization: Bearer <accessToken>
x-csrf-token: <token>

{ "provider": "razorpay", "amount": 99.50 }
// 200 response
{
  "provider": "razorpay",
  "order": { "orderId": "order_Nktp...", "status": "captured", ... }
}

8. Order status

GET /payments/order/:id?provider=razorpay
Authorization: Bearer <accessToken>

// 200 response
{ "provider": "razorpay", "order": { "orderId": "...", "status": "paid", ... } }
Pass the provider in the query string The status route needs ?provider=razorpay (or whichever) so the service knows which gateway to query. Without it the route returns 400 with "Unknown or disabled provider (pass ?provider=)".

Admin routes are bearer + requireRole('admin') guarded. They read the persisted order/transaction stores (populated by registerPaymentRoutes + webhooks).

11. Browser checkout flow — full example

// checkout.ts — the frontend pattern (simplified from apps/frontend/lib/payments.ts)
async function refreshCsrf() { /* GET /csrf-token — see Auth guide */ }
function csrfHeaders() { return { 'x-csrf-token': csrfToken }; }
function authHeaders() { return { authorization: 'Bearer ' + accessToken }; }

async function createOrder(provider, amount, currency) {
  await refreshCsrf();
  const r = await fetch('/payments/order', {
    method: 'POST', credentials: 'include',
    headers: { 'content-type': 'application/json', ...csrfHeaders(), ...authHeaders() },
    body: JSON.stringify({ provider, amount, currency }),
  });
  if (!r.ok) throw new Error((await r.json()).error ?? r.statusText);
  return (await r.json()).order;
}

async function captureOrder(orderId, provider, amount) {
  await refreshCsrf();
  const r = await fetch(`/payments/order/${orderId}/capture`, {
    method: 'POST', credentials: 'include',
    headers: { 'content-type': 'application/json', ...csrfHeaders(), ...authHeaders() },
    body: JSON.stringify({ provider, amount }),
  });
  return (await r.json()).order;
}

async function getOrderStatus(orderId, provider) {
  const r = await fetch(`/payments/order/${orderId}?provider=${provider}`, {
    headers: { ...authHeaders() },
    credentials: 'include',
  });
  return (await r.json()).order;
}

// Full checkout flow
async function checkout() {
  // 1. Create the order with the gateway
  const order = await createOrder('razorpay', 99.50, 'INR');

  // 2. Redirect to hosted checkout (customer pays on the gateway page)
  window.location.href = order.paymentUrl;

  // 3. Gateway redirects back to returnUrl — poll status there
  //    (the webhook is the authoritative confirmation; this is for UI)
}

// On the return page (e.g. /checkout/return?order_id=...)
async function confirmAndCapture(orderId) {
  const order = await getOrderStatus(orderId, 'razorpay');
  if (order.status === 'authorized') {
    await captureOrder(orderId, 'razorpay', order.amount);
  }
  // Show success/failed UI based on order.status
}
Testing without live keys The HttpTransport is injectable, so unit/integration tests pass a mock transport — no live gateway calls. The log-equivalent for payments is to simply not set keys: createPayments returns a service with an empty providers map, and the order route returns 400 with a clear "Enabled: none" message.

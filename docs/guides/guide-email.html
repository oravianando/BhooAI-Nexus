GUIDE

Send Email The Nexus email service — providers (log for dev, SMTP for prod), a tiny template engine, and a retry queue, with working register-confirmation and password-reset examples.

@bhooai/nexus-email is a small, dependency-light email service: a pluggable provider (log or smtp via nodemailer), a template engine with {{var}} / {{#if}} / {{#each}}, and an optional send queue with exponential backoff retries. No Handlebars, no external queue daemon.

1. Config in nexus.config.ts

The email section of the config selects the provider and the from address. SMTP connection details go in .env, not the config file.

// nexus.config.ts
email: {
  provider: 'log',              // 'log' for dev, 'smtp' for prod
  from: 'no-reply@myapp.com',
  // smtp: { host, port, secure, user, pass } — set via .env in prod
}

2. SMTP settings in .env

When provider: 'smtp', the service reads SMTP connection details from config. The cleanest path is to put them in .env via NEXUS_EMAIL_SMTP_* env vars, which map to email.smtp.{host,port,secure,user,pass}.

# .env — SMTP provider (production)
NEXUS_EMAIL_PROVIDER=smtp
NEXUS_EMAIL_FROM=no-reply@myapp.com
NEXUS_EMAIL_SMTP_HOST=smtp.your-provider.com
NEXUS_EMAIL_SMTP_PORT=587
NEXUS_EMAIL_SMTP_SECURE=false          # true for port 465 (implicit TLS)
NEXUS_EMAIL_SMTP_USER=apikey
NEXUS_EMAIL_SMTP_PASS=SG.xxxxxxxxxxxxx
Env → config mapping NEXUS_* env vars map to nested config by splitting on _. So NEXUS_EMAIL_SMTP_HOST becomes email.smtp.host. Boolean fields (secure) coerce true/false strings; numeric fields (port) parse to integers.

3. The TemplateEngine

The engine supports {{var}} interpolation, nested paths ({{a.b.c}}), {{#if cond}}…{{else}}…{{/if}} conditionals, and {{#each items}}…{{this}}…{{/each}} iteration over arrays. Each transformation runs as a sequential render chain: each → if → interpolate.

import { TemplateEngine } from '@bhooai/nexus-email';

const templates = new TemplateEngine();
templates.register('welcome', `
  <h1>Welcome, {{name}}!</h1>
  <p>Verify your email to get started.</p>
  <a href="{{verifyUrl}}">Verify now</a>
`);

templates.register('reset', `
  <h1>Reset your password</h1>
  <p>We received a request to reset your password.</p>
  {{#if resetUrl}}
    <a href="{{resetUrl}}">Reset now</a>
  {{else}}
    <p>If this wasn't you, ignore this email.</p>
  {{/if}}
`);

templates.register('digest', `
  <h1>Your weekly digest</h1>
  <ul>
  {{#each items}}
    <li>{{this.title}} — {{this.url}}</li>
  {{/each}}
  </ul>
`);

4. email.send() API

createEmail(config, { templates }) returns an EmailService with send() and queue(). When template is named, the service renders it against vars before handing the rendered HTML to the provider.

import { createEmail, TemplateEngine } from '@bhooai/nexus-email';

const templates = new TemplateEngine();
templates.register('welcome', '<h1>Welcome, {{name}}!</h1><p>Verify {{email}}.</p>');
const email = createEmail(config.email, { templates });

await email.send({
  to: 'ravi@example.com',
  template: 'welcome',
  vars: { name: 'Ravi', email: 'ravi@example.com' },
});

5. Example: welcome email on user registration

The scaffold already registers a welcome template in main.ts. To send it, hook into your registration flow.

// apps/backend/src/modules/auth/authRoutes.ts (inside /auth/register)
const [user] = await User.create({ email, name, passwordHash, roles });
const pair = await service.login({ userId: String(user._id), roles });

// Send the welcome email (fire-and-forget; don't block registration)
email.send({
  to: user.email,
  template: 'welcome',
  vars: { name: user.name ?? user.email, verifyUrl: `https://myapp.com/verify?token=...` },
}).catch((err) => log.warn('welcome email failed', { msg: err.message }));

setAuthCookies(ctx, pair, { ... });
ctx.json({ user: publicUser(user), accessToken: pair.accessToken, refreshToken: pair.refreshToken });
// The 'welcome' template (registered in main.ts)
templates.register('welcome', `
  <h1>Welcome, {{name}}!</h1>
  <p>Verify your email to get started.</p>
  <a href="{{verifyUrl}}">Verify now</a>
`);

6. Example: password reset email

// Register the template
templates.register('reset', `
  <h1>Reset your password</h1>
  <p>We received a request to reset your password.</p>
  <a href="{{resetUrl}}">Reset now</a>
  <p>If this wasn't you, ignore this email.</p>
`);

// Route: POST /auth/password/request-reset
router.post('/auth/password/request-reset', async (ctx) => {
  const { email } = (ctx.body ?? {}) as { email?: string };
  const User = getUserModel();
  const user = await User.findOne({ email: email?.toLowerCase() }).lean();
  // Don't reveal whether the email exists — always 200
  if (!user) { ctx.json({ ok: true }); return; }

  const resetToken = randomBytes(24).toString('hex');
  await User.updateOne({ _id: user._id }, { $set: { resetToken, resetExpires: new Date(Date.now() + 15 * 60_000) } });

  await email.send({
    to: user.email,
    template: 'reset',
    vars: { name: user.name ?? user.email, resetUrl: `https://myapp.com/reset?token=${resetToken}` },
  });

  ctx.json({ ok: true });
});
Don't leak account existence Always return { ok: true } for password-reset requests, regardless of whether the email exists. Otherwise you've built an email-enumeration endpoint.

7. Using the log provider for development

When email.provider === 'log', the LogProvider prints the rendered email to the console (or a custom logger) instead of sending it. No SMTP server needed.

// nexus.config.ts — development default
email: { provider: 'log', from: 'no-reply@myapp.local' }
// Console output when email.send() is called
[nexus-email] {"name":"ravi@example.com","subject":"Welcome","text":"<h1>Welcome, Ravi!</h1>..."}
Tests use a JSON transport The SmtpProvider accepts an injectable nodemailer Transport. Tests pass jsonTransport so no network is involved and the rendered email is captured in-memory.

8. Switching to smtp for production

Flip the provider and add the SMTP env vars. No code changes — the same email.send() call now goes through nodemailer.

# .env (production)
NEXUS_EMAIL_PROVIDER=smtp
NEXUS_EMAIL_FROM=no-reply@myapp.com
NEXUS_EMAIL_SMTP_HOST=smtp.sendgrid.net
NEXUS_EMAIL_SMTP_PORT=587
NEXUS_EMAIL_SMTP_SECURE=false
NEXUS_EMAIL_SMTP_USER=apikey
NEXUS_EMAIL_SMTP_PASS=SG.xxxxxxxxxxxxx

Common providers: SendGrid (smtp.sendgrid.net, user apikey), Mailgun, Postmark, AWS SES, Gmail (for low volume only — use an app password, not your main password).

9. The send queue (optional)

For background delivery with retries, configure a queue backend. The worker drains it with exponential backoff up to maxAttempts (default 3).

const email = createEmail(config.email, { templates, queue: new MemoryQueue() });

await email.queue({ to: user.email, template: 'welcome', vars: { ... } });
email.startWorker();   // idempotent — drains the queue with retries

The backoff is 250ms * 2^(attempt-1). After maxAttempts failures the job is dropped (in production this should go to a dead-letter store).

From-address reputation Use a real from on a domain you control, with SPF/DKIM/DMARC configured. no-reply@myapp.local is fine for log mode but will be rejected or spam-foldered by every real inbox.

Install & Setup

npm install fails on mediasoup native build

Symptom: npm install hangs or errors on mediasoup with a C++ compiler error.

Fix: Mediasoup compiles a native worker binary. Ensure you have build tools installed:

  • Windows: npm install -g windows-build-tools or install Visual Studio Build Tools with the "Desktop development with C++" workload
  • macOS: xcode-select --install
  • Linux: sudo apt install build-essential python3

If you don't need WebRTC, skip mediasoup by removing mediasoup from apps/frontend/package.json and disabling the realtime module in nexus.config.ts.

nexus init can't find templates

Symptom: Error: templates directory not found at ...

Fix: The CLI resolves templates relative to its own location. If you're running from a global install, the templates may not be included. Install locally instead: npm install bhooai-nexus && npx nexus init my-app.

nexus doctor reports MongoDB unreachable

Symptom: [X] mongodb localhost:27017 unreachable

Fix:

  • Verify MongoDB is running: mongosh --eval "db.runCommand({ ping: 1 })"
  • Check MONGODB_URI in .env — format: mongodb://localhost:27017/my-app
  • Start MongoDB with Docker: docker run -d -p 27017:27017 mongo:7

nexus doctor reports Redis unreachable

Symptom: [X] redis localhost:6379 unreachable

Fix: Redis is optional — the framework degrades gracefully without it. To use it: docker run -d -p 6379:6379 redis:7

Port already in use

Symptom: EADDRINUSE: address already in use 0.0.0.0:4000

Fix: nexus dev auto-allocates the next free port, but if a stale process holds the port:

# Find and kill the process
lsof -i :4000       # macOS/Linux
netstat -ano | findstr :4000  # Windows

Or set NEXUS_SERVER_PORT=4001 in .env.

PostCSS & Tailwind

Cannot find module 'postcss-import'

Symptom:

Loading PostCSS Plugin failed: Cannot find module 'postcss-import'
Require stack:
- apps/frontend/postcss.config.js

Cause: The preset returns plugin names as strings, so PostCSS tries to resolve them from the consumer's node_modules instead of the preset's.

Fix: Update @bhooai/nexus-postcss to the latest version. The preset imports and instantiates plugins internally — consumer projects don't need postcss-import, postcss-nested, etc. installed directly.

# In the framework root
npm update @bhooai/nexus-postcss
npm install  # re-hoist workspaces

No utility classes were detected

Symptom: Tailwind build succeeds but outputs a warning:

warn - No utility classes were detected in your source files.

Cause: Your tailwind.config.js content paths don't match where your JSX/TSX files are, or your components don't use any Tailwind class names yet.

Fix:

  • Check content in tailwind.config.js includes './src/**/*.{ts,tsx}'
  • If using createPreset(), pass content: ['./src/**/*.{ts,tsx}']
  • If your components only use inline styles, this warning is expected and harmless

@apply fails in custom CSS

Symptom: Error: @apply is not supported or Cannot apply unknown utility class

Fix:

  • Ensure @tailwind base / components / utilities directives are present before any @apply usage in your CSS file
  • Ensure the postcss-nested plugin runs before tailwindcss — the preset handles this automatically
  • Check the class name exists in your Tailwind theme (custom classes need to be defined first)

theme.css tokens not appearing in built CSS

Symptom: var(--nexus-bg) resolves to nothing in the browser.

Fix: Ensure the @import is the first line of index.css, before @tailwind directives:

@import '@bhooai/nexus-postcss/theme.css';

@tailwind base;
@tailwind components;
@tailwind utilities;

If the @import comes after @tailwind, postcss-import may not inline it correctly. Verify postcss.config.js uses createPreset() with import: true (the default).

ERR_MODULE_NOT_FOUND on postcss.config.js

Symptom: Failed to load PostCSS config: ERR_MODULE_NOT_FOUND: Cannot find module '@bhooai/nexus-postcss/src/plugins.js'

Cause: The preset's package.json exports point at a .ts file instead of .js.

Fix: Update to the latest @bhooai/nexus-postcss — the package ships .js files. Run npm install in the framework root to re-hoist the workspace.

Dev Server

Vite proxy 404 on /auth or /graphql

Symptom: Frontend requests to /auth/login return 404.

Cause: The Vite dev server proxies API routes to the backend. If the backend isn't running or is on a different port, the proxy fails.

Fix:

  • Verify the backend is running: curl http://localhost:4000/health
  • Check NEXUS_SERVER_PORT in .env matches the Vite proxy target
  • Run npm run dev (supervisor) instead of starting only the frontend

Frontend builds but page is blank

Symptom: Vite dev server starts, page loads, but nothing renders.

Fix: Check browser console for errors. Common causes:

  • #root element missing in index.html
  • CSS @import failing silently — check Network tab for 404 on theme.css
  • React component throwing in render — check console for the stack trace

CSS not hot-reloading

Symptom: Edits to index.css don't appear in the browser.

Fix:

  • Ensure import './index.css' is in main.tsx (not App.tsx)
  • Hard-refresh the browser (Ctrl+Shift+R) — Vite HMR can miss CSS-only changes
  • Check the Vite terminal for PostCSS errors that may silently fail

Auth & Security

CSRF token mismatch

Symptom: 403 Forbidden — invalid csrf token on POST requests.

Fix:

  • Fetch a CSRF token before any mutating request: GET /csrf-token → read token from response
  • Include the token in the x-csrf-token header
  • Send credentials: fetch(url, { credentials: 'include' })
  • The token is cookie-based — ensure cookies aren't blocked by browser settings

JWT secret mismatch across cluster nodes

Symptom: Auth works on the master but slaves reject the token.

Fix: Set the same NEXUS_AUTH_JWT_SECRET in .env on every node. Slaves verify the access token locally using the shared secret.

OAuth redirect loop

Symptom: Google/Facebook OAuth redirects back to the login page repeatedly.

Fix: Check that the OAuth redirect URI in your provider's console matches http://localhost:4000/auth/google/callback (or your deployed domain). The path must be exactly /auth/{provider}/callback.

Session reuse detection logs user out

Symptom: User is logged out with a "session reused" message.

Cause: The same refresh token was used from two locations/tabs simultaneously. Nexus detects this as a session hijack attempt and invalidates the session.

Fix: This is expected security behavior. Use separate sessions per device. If testing locally, use different browser profiles instead of tabs.

Cluster & Mesh

Slave node won't link to master

Symptom: nexus cluster link http://master:7575 fails or node doesn't appear in the admin Cluster tab.

Fix:

  • Verify the master node agent is running on the target host
  • Check the pairing token matches — get it from the master admin Cluster tab
  • Ensure firewall allows the node agent port (default 7575)
  • Use --token <token> if the token isn't in the config

Load balancer returns 503

Symptom: 503 pinned_node_down or 503 no_healthy_nodes

Fix:

  • pinned_node_down — the path-pinned node is offline. Start it or remove the pin from Cluster → Path routing
  • no_healthy_nodes — no backend nodes are registered. Link at least one slave or enable cluster.failOpenSingleNode to fall back to the master's own backend

nexus sync overwrites Dockerfile edits

Symptom: Manual edits to Dockerfile disappear after running nexus sync.

Fix: nexus sync regenerates Dockerfiles from nexus.config.ts. Don't edit Dockerfiles manually — put port changes, service toggles, etc. in nexus.config.ts and re-run nexus sync.

MongoDB & Data

Connection string format

Symptom: MongoServerError: Authentication failed or Invalid scheme.

Fix: Use the standard URI format:

MONGODB_URI=mongodb://user:password@localhost:27017/dbname
# Or with options:
MONGODB_URI=mongodb://localhost:27017/dbname?authSource=admin

For MongoDB Atlas: mongodb+srv://user:pass@cluster.xxxxx.mongodb.net/dbname

ODM schema validation errors

Symptom: ValidationError: path "email" is required or ValidationError: expected string, got number.

Fix: Check your model schema definition. The Nexus ODM validates types and required fields before writing to MongoDB. Ensure the data you're saving matches the schema's field types.

Transaction aborts

Symptom: MongoServerError: Transaction aborted or TransactionTooLarge.

Fix:

  • Ensure MongoDB is running as a replica set (transactions require it): mongod --replSet rs0 --bind_ip_all
  • Initialize: mongosh --eval "rs.initiate()"
  • Keep transactions small — large bulk writes may exceed the 16MB BSON limit

AI Server

Python venv not activated

Symptom: ModuleNotFoundError: No module named 'fastapi' when starting the AI server.

Fix:

# Create and activate venv
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

# Install deps
pip install -r apps/ai-server/requirements.txt

# Or use nexus pysetup
npm run pysetup

OpenAI API key missing

Symptom: openai.AuthenticationError: Incorrect API key or the AI provider falls back to Ollama.

Fix: Set the key in .env:

AI_OPENAI_KEY=sk-...

If no OpenAI key is set, the AI server automatically uses Ollama (if running on localhost:11434).

SSE stream cuts off

Symptom: AI chat streaming starts but stops mid-response.

Fix:

  • Check the backend terminal for proxy errors — the Node backend proxies SSE from the Python server
  • Ensure the Python AI server is running: curl http://localhost:8000/health
  • Some proxies/load balancers buffer SSE — disable response buffering in nginx if behind a reverse proxy

Ollama connection refused

Symptom: ConnectionRefusedError: [Errno 111] Connection refused when the AI server tries Ollama.

Fix: Start Ollama locally: ollama serve (defaults to localhost:11434). Pull a model: ollama pull llama3.

Admin Console

Admin page is blank

Symptom: http://localhost:3300 loads but renders nothing.

Fix:

  • Check browser console for module loading errors
  • Ensure @bhooai/admin resolves — run npm install in the framework root
  • Check tailwind.config.js content paths include ../../packages/nexus-admin/src/**/*.{ts,tsx} — missing paths cause Tailwind to not generate the admin's utility classes

@bhooai/admin/style.css 404

Symptom: Failed to resolve module @bhooai/admin/style.css

Fix: The @bhooai/admin package's exports map includes "./style.css": "./src/index.css". If this 404s, the package version is stale. Run npm install to re-link the workspace.

Mobile navbar hamburger missing

Symptom: On mobile screens, the navigation links disappear and there's no way to open the menu.

Fix: The navbar should include a hamburger toggle button that appears on screens ≤ 900px. If it's missing:

  • Check App.tsx has a menuOpen state and a .menu-toggle button
  • Check index.css has .menu-toggle { display: none } on desktop and @media (max-width: 900px) { .menu-toggle { display: flex } }
  • Check .mobile-links panel is present and toggled by the button

Build & Deploy

tsc -b fails with project reference errors

Symptom: error TS6306: Referenced project must have setting "composite": true

Fix: This is a known issue with the TypeScript project references in the monorepo. Ensure tsconfig.base.json has "composite": false (or remove the references from the failing project's tsconfig.json). For a quick build, use vite build directly instead of tsc -b && vite build.

Docker build fails on npm install

Symptom: Docker RUN npm install fails with workspace resolution errors.

Fix:

  • Ensure Dockerfile copies package.json and package-lock.json before npm install
  • The monorepo uses file: workspace links — all workspace packages must be present in the build context
  • Use .dockerignore to exclude node_modules and dist

vite build CSS missing Tailwind utilities

Symptom: Production build succeeds but the CSS file is tiny and Tailwind utility classes don't work.

Fix:

  • Check tailwind.config.js content paths include all source directories with Tailwind class names
  • If using createPreset(), pass content or extraContent to scan additional directories
  • Run NODE_ENV=production npx vite build — Tailwind purges unused classes based on what it finds in content paths

PostCSS config not loaded

Symptom: Failed to load PostCSS config error during vite build.

Fix:

  • Ensure postcss.config.js is in the app root (same level as vite.config.ts)
  • Check the file uses export default (ESM) not module.exports (CJS) — the project package.json has "type": "module"
  • Verify @bhooai/nexus-postcss is in devDependencies and installed: npm ls @bhooai/nexus-postcss

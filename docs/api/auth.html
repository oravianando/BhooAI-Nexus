AuthService

High-level auth orchestrator. The app verifies credentials (via verifyPassword + its user store) and calls login() to mint a session and token pair. Refresh tokens are rotated on every refresh and bound to a session family; reuse of a previously-rotated token revokes the whole family (refresh-token theft detection).

const auth = new AuthService(
  { secret, algorithm: 'HS256', issuer, audience, accessTtl: 900, refreshTtl: 604800 },
  new MemorySessionStore(), // or your Redis-backed SessionStore
);

const pair = await auth.login({ userId, roles, meta: { ip } });
// pair = { accessToken, refreshToken, sessionId, refreshExpiresAt }

const claims = await auth.verifyAccessToken(token);
const fresh = await auth.refresh(refreshToken); // rotation + reuse detection
await auth.logout(sessionId);
await auth.logoutAll(userId);

login(input)

Create a session in the store and return a fresh access + refresh token pair bound to it.

refresh(refreshToken)

async refresh(refreshToken: string): Promise<TokenPair>

Verify a refresh token, rotate it (new jti), and return a fresh pair. If the presented token's jti no longer matches the session's currentJti, the token has been reused after rotation → the entire session family is revoked and an AuthenticationError('Refresh token reuse detected; session revoked') is thrown.

Reuse detection Each refresh mints a new jti and records it on the session. A stolen, already-rotated token presented after the legitimate user has refreshed trips the mismatch and burns the whole family — the attacker and the victim must both re-authenticate.

CSRF

Double-submit cookie pattern plus an origin/referer check on unsafe methods. Safe methods (GET, HEAD, OPTIONS, TRACE) are exempt; on safe requests a token cookie is set (reused across concurrent safe requests to avoid rotation races) and exposed via ctx.state.csrfToken. On unsafe requests, the header token must equal the cookie token.

CsrfOptions

FieldTypeDefaultDescription
cookieName?string'nexus_csrf'Cookie name holding the double-submit token.
tokenName?string'x-csrf-token'Header / body field name carrying the token on unsafe requests.
trustedOrigins?string[][]Trusted origin hosts for the origin/referer check. If omitted, the origin check is skipped.
safeMethods?string[]['GET','HEAD','OPTIONS','TRACE']Methods exempt from CSRF.
cookie?{ path?, secure?, sameSite?, domain? }{ path:'/', sameSite:'lax', secure:false }Cookie attributes.

csrf(options?)

function csrf(options: CsrfOptions = {}): Middleware

The CSRF middleware. Handles HTTP requests only. Unsafe requests require a matching x-csrf-token header (or body field) equal to the cookie token, and (when trustedOrigins is non-empty) an Origin (or Referer) that matches a trusted origin.

router.use(csrf({ trustedOrigins: [origin] }));
// safe GETs set ctx.state.csrfToken + the nexus_csrf cookie
router.get('/csrf-token', (ctx) => ctx.json({ token: ctx.state.csrfToken }));
WS upgrades are NOT covered csrf() only handles HTTP requests. WebSocket upgrade requests have no CORS preflight and bypass the HTTP middleware pipeline — to enforce CSRF + origin on the WS upgrade, call checkWsUpgrade() explicitly in your upgrade handler.
Loopback origins ignore the port localhost, 127.0.0.1, and ::1 match any trusted loopback origin regardless of port. Docker / port-forwarding commonly remaps host ports (e.g. container :3001 published on the host as :3011), so a strict host:port match would wrongly reject the admin/frontend dev servers. Non-loopback origins must match a trusted entry exactly (host, full origin, or a prefix).

issueCsrfToken(ctx, options?)

function issueCsrfToken(ctx: RequestContext, options: CsrfOptions = {}): string

Helper for handlers/endpoints to mint a fresh CSRF token (e.g. a /csrf-token route). Sets the HttpOnly cookie and returns the token so the handler can echo it to the client.

router.get('/csrf-token', (ctx) => {
  const token = issueCsrfToken(ctx, { cookieName: 'nexus_csrf' });
  ctx.json({ token }); // also sets the HttpOnly cookie
});
trustedOrigins is a no-op here issueCsrfToken only reads cookieName / cookie from the options. Passing trustedOrigins has no effect on token issuance — the origin check lives in the csrf() middleware, not in the issuer.

checkWsUpgrade(headers, options?)

function checkWsUpgrade(
  headers: Record<string, string | string[] | undefined>,
  options: CsrfOptions = {},
): void

CSRF + origin check for the WebSocket upgrade request. WS upgrades have no CORS preflight and bypass the HTTP middleware pipeline, so csrf() does not cover them — call this explicitly in your upgrade handler. Throws AuthenticationError on a bad origin or a token mismatch.

Origin: if trustedOrigins is non-empty, the Origin header must match a trusted origin (same loopback-port rule as csrf()). Token: the CSRF cookie token must equal the first Sec-WebSocket-Protocol subprotocol value (the client sends the token as the subprotocol).

httpServer.on('upgrade', (req, socket, head) => {
  try {
    checkWsUpgrade(req.headers, { trustedOrigins, cookieName: 'nexus_csrf' });
    wss.handleUpgrade(req, socket, head, (ws) => { ... });
  } catch {
    socket.destroy();
  }
});

Password

Hashing via bcryptjs (pure-JavaScript, API-compatible with the native bcrypt binding). The pure-JS implementation is chosen deliberately so the framework builds on Windows without node-gyp / native toolchains.

hashPassword(plaintext, rounds?)

async function hashPassword(plaintext: string, rounds = 12): Promise<string>

Hash a plaintext password with a salt cost of rounds (default 12). Throws if plaintext is empty or not a string.

verifyPassword(plaintext, hash)

async function verifyPassword(plaintext: string, hash: string): Promise<boolean>

Verify a plaintext password against a previously-hashed value. Returns false (never throws) on a mismatch or malformed hash.

isBcryptHash(hash)

function isBcryptHash(hash: string): boolean

True if hash looks like a bcrypt hash (/^\$2[abxy]\$\d{2}\$/) — used to detect legacy / plaintext-stored passwords before rehashing.

RBAC

A RoleRegistry maps role names to a set of permissions; roles can inherit from other roles via the inherits option. permissionsFor(role) resolves the full transitive permission set.

RoleDefinition

FieldTypeDescription
permissions?string[]Permissions granted by the role.
inherits?string[]Other roles whose permissions are inherited (transitive).

RoleRegistry

class RoleRegistry {
  define(name: string, def: RoleDefinition): this;
  defineAll(map: Record<string, RoleDefinition>): this;
  permissionsFor(role: string, seen?: Set<string>): Set<string>;
  can(role: string, permission: string): boolean;
  canAny(roles: string[], permission: string): boolean;
}
  • define(name, def) — register one role; chainable.
  • defineAll(map) — register many roles from a record; chainable.
  • permissionsFor(role) — resolve the full transitive permission set for a role (cycle-safe via a seen set).
  • can(role, permission) — true if the role grants the permission (transitively).
  • canAny(roles, permission) — true if any of the user's roles grants the permission.
const registry = new RoleRegistry().defineAll({
  viewer:  { permissions: ['read'] },
  editor:  { permissions: ['write'], inherits: ['viewer'] },
  admin:   { permissions: ['delete', 'manage-users'], inherits: ['editor'] },
});
registry.can('editor', 'read');    // true (inherited)
registry.canAny(['editor'], 'delete'); // false

Middleware that requires an authenticated user (sets nothing; pairs with authToken). Throws AuthenticationError if ctx.state.user is unset.

Middleware factory — variadic: pass one or more roles. Requires the user to hold at least one of them; otherwise throws AuthorizationError (403).

Middleware factory — takes two arguments: a RoleRegistry and the permission to check. Requires that any of the user's roles grants the permission (via registry.canAny); otherwise throws AuthorizationError (403).

router.delete('/users/:id', deleteUser, [
  authToken(auth),
  requirePermission(registry, 'manage-users'),
]);

Build the Google consent URL with PKCE (code_challenge_method: S256), access_type: offline, and prompt: consent. Redirect the user here to start the flow.

  code: string, config: GoogleOAuthConfig, verifier: string,
): Promise<{ accessToken: string; refreshToken?: string; idToken?: string; expiresAt: number }>

Exchange the authorization code for Google tokens using the PKCE verifier. Returns the access token, optional refresh/id token, and an expiresAt (ms epoch). Throws on a non-2xx response.

Fetch the Google userinfo profile (openidconnect.googleapis.com/v1/userinfo) and normalize it to OAuthProfile.

buildFacebookAuthUrl(config, state)

function buildFacebookAuthUrl(config: FacebookOAuthConfig, state: string): string

Build the Facebook consent URL. Note the different signature from Google: Facebook takes only state (no PKCE verifier — Facebook OAuth does not support PKCE), and scopes are joined with , rather than a space.

exchangeFacebookCode(code, config)

async function exchangeFacebookCode(
  code: string, config: FacebookOAuthConfig,
): Promise<{ accessToken: string; expiresAt: number }>

Exchange the authorization code for a Facebook access token. No verifier argument (unlike Google). Returns the access token and expiresAt (ms epoch); Facebook does not return a refresh token in this flow.

fetchFacebookProfile(accessToken, apiVersion?)

async function fetchFacebookProfile(accessToken: string, apiVersion = 'v19.0'): Promise<OAuthProfile>

Fetch the Facebook /me profile (id,name,email,first_name,last_name,picture) and normalize it to OAuthProfile. Extra apiVersion argument (defaults to 'v19.0') not present on the Google helper. Email-verified is treated as true when an email is present (Facebook marks email-verified accounts).

Full Google flow example

const google: GoogleOAuthConfig = {
  clientId, clientSecret,
  redirectUri: 'http://localhost:4000/auth/google/callback',
  scope: ['openid', 'email', 'profile'],
};
const stateStore = new MemoryOAuthStateStore();

// 1. start
router.get('/auth/google', (ctx) => {
  const state = generateState();
  const verifier = generatePkceVerifier();
  await stateStore.set(state, { provider: 'google', verifier, redirect: ctx.query.redirect }, 300_000);
  ctx.redirect(buildGoogleAuthUrl(google, { state, verifier }));
});

// 2. callback
router.get('/auth/google/callback', async (ctx) => {
  const flow = await stateStore.consume(ctx.query.state);
  if (!flow) throw new AuthenticationError('Invalid state');
  const tokens = await exchangeGoogleCode(ctx.query.code, google, flow.verifier);
  const profile = await fetchGoogleProfile(tokens.accessToken);
  // → upsert user, call auth.login({ userId, roles }), setAuthCookies(ctx, pair, …)
});
Facebook flow is the same shape, minus PKCE Replace the start step with ctx.redirect(buildFacebookAuthUrl(fb, state)) and the callback with exchangeFacebookCode(code, fb) → fetchFacebookProfile(token). No verifier, no code_challenge.

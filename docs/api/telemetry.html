@bhooai/nexus-telemetry Telemetry API Structured logging, metrics, and request/trace-id propagation.

The observability backbone. A dependency-free structured logger with JSON/pretty output, redaction, and a rotating file transport; a minimal counters & histograms registry with both JSON and Prometheus exposition; and a small AsyncLocalStorage-based trace context for propagating request/trace ids across async boundaries.

Logger — types

LogLevel & LEVEL_ORDER

type LogLevel = 'trace' | 'debug' | 'info' | 'warn' | 'error' | 'fatal';
const LEVEL_ORDER: Record<LogLevel, number> = {
  trace: 10, debug: 20, info: 30, warn: 40, error: 50, fatal: 60,
};

Six severity levels, ordered low → high. A record at level L is emitted only when LEVEL_ORDER[L] >= LEVEL_ORDER[configuredLevel]; everything below the configured level is dropped. trace is the noisiest, fatal the most severe.

LogRecord

interface LogRecord {
  level: LogLevel;
  time: number;      // Date.now() epoch ms
  msg: string;
  [key: string]: unknown;   // bindings + per-call data
}

The internal shape of every emitted record. Bindings (from the constructor or child()) and the per-call data object are spread into the record alongside level, time, and msg.

LoggerOptions

interface LoggerOptions {
  level?: LogLevel;
  format?: 'json' | 'pretty';
  console?: boolean;
  file?: { dir: string; maxFileSize: number; maxFiles: number };
  redact?: string[];
  bindings?: Record<string, unknown>;
}
FieldTypeDefaultDescription
levelLogLevel'info'Minimum level emitted (see LogLevel).
format'json' | 'pretty''pretty''json' emits one JSON.stringifyed record per line; 'pretty' colorizes the level tag and appends the payload as JSON.
consolebooleantrueWrite to stdout (trace–warn) or stderr (error/fatal) in addition to the file transport.
file{ dir, maxFileSize, maxFiles }— (off)Rotating file transport. Omit to disable. dir is created if missing; the active log is <dir>/nexus.log (appended to).
file.dirstring—Log directory (created with mkdirSync(..., { recursive: true })).
file.maxFileSizenumber—Bytes before rotation. When the running nexus.log reaches this size it is rotated.
file.maxFilesnumber—Rotated files to keep. On rotation, nexus.<i-1>.log is renamed to nexus.<i>.log for i = maxFiles-1 … 1, then the active file becomes nexus.0.log and a fresh nexus.log is opened.
redactstring[][]Field names to replace with '[REDACTED]'. Matched by exact, case-sensitive key (key in record) — not substring, not case-insensitive.
bindingsRecord<string, unknown>{}Default fields merged into every record (e.g. { service: 'api' }). Child loggers inherit and extend these.
File transport When file is set, the logger appends to <dir>/nexus.log and tracks the byte count; once it reaches maxFileSize the file is rotated through nexus.0.log … nexus.<maxFiles-1>.log. Stream errors clear the stream (logging continues to console only) rather than crashing the process.

Logger — class & factory

Logger

class Logger {
  constructor(opts: LoggerOptions = {});
  child(bindings: Record<string, unknown>): Logger;
  setLevel(level: LogLevel): void;
  log(level: LogLevel, msg: string, data?: Record<string, unknown>): void;
  trace(msg: string, data?: Record<string, unknown>): void;
  debug(msg: string, data?: Record<string, unknown>): void;
  info(msg: string, data?: Record<string, unknown>): void;
  warn(msg: string, data?: Record<string, unknown>): void;
  error(msg: string, data?: Record<string, unknown>): void;
  fatal(msg: string, data?: Record<string, unknown>): void;
  close(): Promise<void>;
}

Inbuilt structured logger. Six level methods (trace … fatal) are thin wrappers over the generic log(level, msg, data?). The record carries { level, time, msg, ...bindings, ...data }; redaction runs before formatting; output goes to console and (optionally) the rotating file transport.

MemberDescription
new Logger(opts?)Construct from LoggerOptions. Opens the file stream up front when file is set. All options default sanely (see the table).
child(bindings)Returns a new Logger that inherits level, format, console, file, and redact, merging bindings over the parent's bindings. Per-request loggers are built this way.
setLevel(level)Change the minimum level at runtime (mutates the logger in place; child loggers keep their own copy).
log(level, msg, data?)Generic emit. Builds the LogRecord, redacts, formats, and writes. The six level methods just forward to this.
trace/debug/info/warn/error/fatal(msg, data?)Convenience wrappers — this.log('trace', msg, data), etc.
close()Flush the file transport (stream.end(...)) and resolve. No-op (resolves immediately) when there is no file stream. Call on graceful shutdown so buffered writes land.
 
import { Logger } from '@bhooai/nexus-telemetry';

const log = new Logger({
  level: 'info',                  // trace|debug|info|warn|error|fatal
  format: 'pretty',             // 'json' | 'pretty'
  console: true,
  file: { dir: 'logs', maxFileSize: 10485760, maxFiles: 7 },
  redact: ['password', 'secret', 'authorization'],
  bindings: { service: 'api' },
});

log.info('listening', { port: 4000 });
log.warn('bad origin', { origin: req.headers.origin });
log.error('boom', err);
log.fatal('cannot boot', { cause });

const reqLog = log.child({ requestId: reqId }); // inherits + merges fields
reqLog.debug('hit', { route });

log.setLevel('debug');                       // runtime change
await log.close();                       // flush file transport on shutdown
Redaction is exact Redaction matches exact, case-sensitive field names (key in record). A field named Password is not redacted by redact: ['password']. Nested fields are not traversed — redact top-level keys only.

createLogger(opts?)

function createLogger(opts?: LoggerOptions): Logger

A file-less logger factory for tests and library contexts. Equivalent to new Logger({ console: false, ...opts }) — i.e. it forces console: false unless opts overrides it, and never opens a file stream on its own. Use this in packages/tests where you want a silent or opt-in logger without touching the filesystem.

import { createLogger } from '@bhooai/nexus-telemetry';
const log = createLogger();        // silent by default (console off, no file)
const loud = createLogger({ console: true, level: 'debug' });

MetricsRegistry

import { MetricsRegistry } from '@bhooai/nexus-telemetry';
class MetricsRegistry {
  counter(name: string, help = ''): CounterState;
  histogram(name: string, buckets: number[] = [0.005, 0.01, 0.05, 0.1, 0.5, 1, 5, 10], help = ''): HistogramState;
  inc(name: string, value = 1, labels: Record<string, string> = {}): void;
  observe(name: string, value: number, labels: Record<string, string> = {}): void;
  toJSON(): Record<string, unknown>;
  toPrometheus(): string;
  reset(): void;
}

Minimal counters & histograms with label support. Labels are sorted by key and encoded into the Prometheus-style {k="v",...} suffix, so the same label set in any order maps to one series. Counters store a Map<labelKey, number>; histograms store per-bucket cumulative counts (incremented for every bucket whose le the observation satisfies), plus a sum and total per label set.

MethodDescription
counter(name, help='')Register (or fetch) a counter and return its state. Does not increment — use inc() for that.
histogram(name, buckets=[…], help='')Register (or fetch) a histogram and return its state. Only registers the histogram and its bucket boundaries — it does not record a value. Use observe() to record. Default buckets: [0.005, 0.01, 0.05, 0.1, 0.5, 1, 5, 10].
inc(name, value=1, labels={})Increment the counter name by value (default 1) for the given label set. Auto-registers the counter if not yet seen.
observe(name, value, labels={})Record value into histogram name for the given label set. For each bucket le, the cumulative count is incremented when value <= le; sum and total are updated. Auto-registers the histogram (with default buckets) if not yet seen.
toJSON()JSON snapshot for an admin /metrics endpoint. Counters: { type, help, values }; histograms: { type, help, buckets, counts, sums, totals }.
toPrometheus()Prometheus text exposition format. Emits # HELP (when help is set), # TYPE, then one line per series. Histograms emit _bucket{...,le="..."} (cumulative), _bucket{...,le="+Inf"}, _sum, and _count.
reset()Clear all counters and histograms.
 
import { MetricsRegistry } from '@bhooai/nexus-telemetry';
const metrics = new MetricsRegistry();

// Register a counter (optional — inc() auto-registers too)
metrics.counter('http_requests_total', 'Total HTTP requests');
metrics.inc('http_requests_total', 1, { method: 'GET', route: '/users/:id' });
metrics.inc('http_requests_total',       // value defaults to 1, labels to {});

// Register a histogram with explicit buckets, THEN record values with observe()
metrics.histogram('http_request_ms', [0.1, 0.5, 1, 5], 'Latency in ms');
metrics.observe('http_request_ms', latencyMs, { route: '/users/:id' });

const snapshot = metrics.toJSON();        // for an admin endpoint
const prom = metrics.toPrometheus();      // for a Prometheus scraper
metrics.reset();                          // clear everything (e.g. between tests)
Two-step histograms histogram(name, buckets, help) only registers the histogram (and its bucket boundaries) — it returns HistogramState and does not record a value. To record a measurement, call observe(name, value, labels). Calling histogram('x', value, help) with a number as the second argument will silently treat that number as a one-element buckets array — always register with buckets, then observe.
Counters don't chain counter(name, help) returns the registered counter state — it does not chain .inc(). Increment via the registry's inc(name, value, labels).

Trace — request & trace ids

Generic AsyncLocalStorage-based trace context. It generates and propagates a requestId and traceId across async boundaries within a single Node process — no transport-specific (WebSocket, HTTP, Python) coupling is baked in; downstream code reads currentTrace() and forwards the ids through whatever channel it uses.

TraceContext

interface TraceContext {
  requestId: string;
  traceId: string;
}

A pair of UUIDs. requestId identifies a single request; traceId groups a chain of related requests (e.g. a fan-out). Both default to fresh randomUUID()s but may be seeded from inbound headers via withTrace's existing argument.

withTrace(fn, existing?)

function withTrace<R>(fn: () => R, existing?: Partial<TraceContext>): R

Start a trace context for the lifetime of fn, propagating request/trace ids. Builds a TraceContext from existing (filling any missing id with a fresh randomUUID()), then runs fn inside an AsyncLocalStorage scope so that currentTrace() returns that context from anywhere in the same async chain.

import { withTrace, currentTrace } from '@bhooai/nexus-telemetry';

// seed from inbound headers, or mint fresh ids
const result = withTrace(() => handleRequest(req), {
  requestId: req.headers['x-request-id'] as string | undefined,
  traceId: req.headers['x-trace-id'] as string | undefined,
});

// deep inside handleRequest, still reachable:
const ctx = currentTrace();  // { requestId, traceId } | undefined
log.child({ requestId: ctx?.requestId }).info('handled');

currentTrace()

function currentTrace(): TraceContext | undefined

The current trace context, if any. Returns undefined outside a withTrace scope. Reads the AsyncLocalStorage store, so it's safe across awaits and other async hops within the scope.

newRequestId()

function newRequestId(): string

Generate a standalone id (crypto.randomUUID()) — for headers, log bindings, or anywhere you need a fresh id without entering a trace scope. @bhooai/nexus-core also re-exports a newRequestId used by NexusServer when no x-request-id header is present; both are the same trivial UUID helper.

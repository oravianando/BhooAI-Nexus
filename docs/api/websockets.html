API Reference

WebSockets Two WebSocket endpoints: the realtime room/SFU server on /ws and the GraphQL subscription server on /graphql/ws.

Nexus multiplexes two WebSocket services over the same node:http server that the REST API uses. Both are mounted via noServer upgrade handling so they can share port 4000 (or whatever server.port is configured to) with the HTTP router.

Realtime WebSocket — ws://host/ws

The RealtimeServer from @bhooai/nexus-realtime powers rooms, WebRTC signaling, the mediasoup SFU, and cross-instance Redis fanout. See the Realtime API page for the full class reference (RealtimeServer, RedisPubSubAdapter, MediasoupAdapter) and the exported types (Connection, ClientMessage, ServerMessage, MediaAction).

AspectDetail
URLws://<host>/ws (upgrade handled by RealtimeServer, default RealtimeServerOptions.path)
AuthAccess token via ?token=<accessToken> query param, or sent as the first entry of Sec-WebSocket-Protocol; verified by RealtimeServerOptions.authService
CSRFOptional origin check when RealtimeServerOptions.csrfOptions is set (typically config.ws.requireCsrf ? { trustedOrigins })
FramingJSON text frames; one ClientMessage / ServerMessage per frame, { type, ... }
FanoutRealtimeServerOptions.adapter — defaults to MemoryPubSubAdapter; pass a RedisPubSubAdapter to mirror join/leave/broadcast across instances

Client → Server (ClientMessage)

typePayloadEffect
ping—Server replies pong (keepalive)
join{ room }Join a room; server replies joined with peers
leave{ room }Leave a room; server replies left
offer / answer / candidate{ to, sdp } | { to, candidate }WebRTC signaling relayed to the target peer
broadcast{ room, event, data }Fan out an event to every other peer in the room
media{ action, payload }mediasoup SFU request (request/response, 8s timeout)

Server → Client (ServerMessage)

typePayloadWhen
pong—Reply to ping
error{ message, code? }Any malformed / unauthorized message
joined{ room, peers }You joined room; peers = other members
left{ room }You left the room
peer-joined / peer-left{ room, peer }Another peer joined/left a room you're in (never echoed to the originator)
offer / answer / candidate{ from, sdp } | { from, candidate }Incoming WebRTC signaling from another peer
broadcast{ room, from, event, data }A peer (not you) broadcast an event to the room
media{ action, payload }mediasoup SFU response

Connection example

const token = '<accessToken>';
const ws = new WebSocket(`ws://localhost:4000/ws?token=${token}`);
ws.addEventListener('open', () => {
  ws.send(JSON.stringify({ type: 'join', room: 'lobby' }));
});
ws.addEventListener('message', (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type === 'joined') console.log('peers:', msg.peers);
  if (msg.type === 'broadcast') console.log(msg.from, msg.event, msg.data);
});
// broadcast to the room
ws.send(JSON.stringify({ type: 'broadcast', room: 'lobby', event: 'chat', data: { text: 'hi' } }));
No echo to self deliverRoom skips the originator, so you never receive your own peer-joined / peer-left / broadcast. Cross-instance signaling (offer/answer/candidate) is published to a conn:<to> Redis channel when the target peer is on another instance.

GraphQL Subscriptions — ws://host/graphql/ws

The subscription transport from @bhooai/nexus-graphql implements the graphql-transport-ws protocol (the one used by Apollo, urql, and graphql-ws).

AspectDetail
URLws://<host>/graphql/ws
SubprotocolMust offer graphql-transport-ws as a Sec-WebSocket-Protocol entry, otherwise the server closes with 400
AuthToken in the connection_init payload ({ token: '<accessToken>' }), or ?token=<accessToken> query
Lifecycleconnection_init → connection_ack → many subscribe / next → complete / ping / pong

Client → Server

typePayloadEffect
connection_init{ payload? }Send auth/headers (payload.token); server replies connection_ack
subscribe{ id, payload: { query, variables?, operationName? } }Start a subscription; server streams next events with the same id
complete{ id }Client cancels the subscription
ping{ payload? }Keepalive probe
pong{ payload? }Reply to a server ping

Server → Client

typePayloadWhen
connection_ack{ payload? }Handshake accepted
next{ id, payload }A subscription yielded a value
error{ id, payload }Subscription errored (parse / validation / resolver)
complete{ id }Subscription ended (server-side complete)
pong{ payload? }Reply to a client ping

Subscription example

import { createClient } from 'graphql-ws';

const client = createClient({
  url: 'ws://localhost:4000/graphql/ws',
  connectionParams: () => ({ token: accessToken }),
});

const unsubscribe = client.subscribe(
  {
    query: `subscription { messageAdded(room: "lobby") { id text from } }`,
    variables: {},
  },
  {
    next: (data) => console.log('event', data),
    error: (err) => console.error('ws error', err),
    complete: () => console.log('stream closed'),
  },
);

// later: unsubscribe() to send `complete` and tear it down
Subprotocol required If your client connects without offering graphql-transport-ws in Sec-WebSocket-Protocol, the server responds with HTTP 400 on the upgrade. Most GraphQL WS clients do this automatically — raw WebSocket users must pass it as the second argument: new WebSocket(url, 'graphql-transport-ws').

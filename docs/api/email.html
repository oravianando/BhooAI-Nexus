@bhooai/nexus-email Email API SMTP via nodemailer, a template engine, and an optional send queue with retries.

Transactional email for the framework. Pick a provider (smtp for nodemailer or log for dev), optionally register named templates, and either send() synchronously or queue() for background delivery with exponential-backoff retries. No Handlebars — the template engine is a tiny in-house string renderer sufficient for transactional email.

Factory — createEmail(config, opts?)

function createEmail(config: EmailConfigLike, opts: CreateEmailOptions = {}): EmailService

Build an EmailService from the email config section. If opts.provider is supplied it wins (useful for tests); otherwise provider:'smtp' with config.smtp constructs an SmtpProvider, and anything else falls back to a LogProvider (dev/test — never sends).

const templates = new TemplateEngine();
templates.register('welcome', '<h1>Welcome, {{name}}!</h1><p>Verify {{email}}.</p>');

const email = createEmail(config.email, {
  templates,
  queue: new MemoryQueue(),
  maxAttempts: 5,
});
email.startWorker();
await email.send({ to: 'ravi@x.com', subject: 'Welcome', template: 'welcome', vars: { name: 'Ravi', email: 'ravi@x.com' } });

EmailProvider

interface EmailProvider {
  readonly name: string;
  send(input: EmailInput): Promise<EmailResult>;
}

The transport abstraction. Implementations: SmtpProvider, LogProvider. Inject a custom one via CreateEmailOptions.provider (or construct EmailService directly).

QueueBackend

interface QueueBackend {
  push(job: EmailInput): Promise<void>;
  close(): Promise<void>;
}

Generic send-queue backend. Implementations also expose a subscribe(consumer) method the EmailService worker hooks into, but that is not part of the interface contract. Queues only push/subscribe/drain — retry/backoff lives in EmailService, not the queues.

Templates — TemplateEngine

class TemplateEngine {
  register(name: string, body: string): void;
  has(name: string): boolean;
  render(name: string, vars?: Record<string, unknown>): string;
  renderString(tpl: string, vars: Record<string, unknown>): string;
}

A minimal, dependency-free template engine for emails. Supports {{var}} interpolation, nested paths ({{a.b.c}}), {{#if cond}}…{{else}}…{{/if}} conditionals (empty arrays are falsy), and {{#each items}}…{{this}}…{{/each}} iteration over arrays. Each transformation is applied as a sequential render chain (each → if → interpolate); #each bodies are rendered recursively per item with this merged into the vars. Unknown interpolation keys render as ''.

MethodDescription
register(name, body)Store a template body string under name.
has(name)True if a template is registered under name.
render(name, vars?)Render the named template; throws if name is unknown. vars defaults to {}.
renderString(tpl, vars)Render an arbitrary template string (used internally by render and to render subject tokens).
 
const tpl = new TemplateEngine();
tpl.register('receipt', '{{#if paid}}Paid{{else}}Pending{{/if}}: {{amount}} ({{#each items}}{{this}} {{/each}})');
tpl.has('receipt');          // true
tpl.render('receipt', { paid: true, amount: '$10', items: ['a', 'b'] }); // "Paid: $10 (a b )"
tpl.renderString('Hi {{user.name}}', { user: { name: 'Maya' } });     // "Hi Maya"

Providers — providers.ts

SmtpProvider

class SmtpProvider implements EmailProvider {
  readonly name = 'smtp';
  constructor(opts: { host; port; secure; user; pass }, customTransport?: Transport);
  send(input: EmailInput): Promise<EmailResult>;
}

SMTP provider backed by nodemailer. The transport is injectable via the optional customTransport argument — tests pass nodemailer's jsonTransport so no network is touched. send() forwards to/cc/bcc/ subject/html/text/attachments/replyTo/ headers straight to sendMail and returns { messageId, envelope, raw, input }.

LogProvider

class LogProvider implements EmailProvider {
  readonly name = 'log';
  constructor(log?: (line: string) => void);
  send(input: EmailInput): Promise<EmailResult>;
}

Dev/test provider: writes a JSON line ({ name, subject, text|html }) to the logger instead of sending. The default logger is console.log('[nexus-email] …'); pass a custom log to capture in tests. Returns { messageId: 'log-<ts>', input }.

renderTemplate(input, engine)

function renderTemplate(input: EmailInput, engine: TemplateEngine): EmailInput

If input.template is set, render it against engine and write the result into html (only when html is not already provided). Also, if the subject contains {{ tokens, render it via renderString. Returns a new EmailInput with html/subject populated; if no template is named, returns input unchanged. Used internally by EmailService.send()/queue().

Queues — queue.ts

Both queue backends expose push(job), subscribe(consumer), and close(). They only enqueue and drain — they do not retry. Retry with exponential backoff is the EmailService worker's job (see EmailService.processWithRetry).

MemoryQueue

class MemoryQueue implements QueueBackend {
  constructor(pollMs = 50);
  push(job: EmailInput): Promise<void>;
  subscribe(consumer: (job: EmailInput) => Promise<void>): void;
  get pending(): number;
  close(): Promise<void>;
}

In-memory queue: push appends to an array; a setInterval poller (pollMs) drains pending jobs to all subscribed consumers. Sufficient for single-instance apps and tests; RedisQueue is the horizontal-scale option. The queue never blocks the sender. push throws if the queue is closed; close() clears the interval.

MemberDescription
constructor(pollMs = 50)Start the drain poller on the given interval (ms).
push(job)Append a job; throws '[nexus-email] queue closed' after close().
subscribe(consumer)Register an async consumer; called per job during drain.
pending (getter)Number of jobs waiting in the buffer.
close()Mark closed and stop the poller.

RedisQueue

class RedisQueue implements QueueBackend {
  constructor(createClient: () => any, key = 'nexus:email:queue', pollMs = 100);
  ensureConnected(): Promise<void>;
  push(job: EmailInput): Promise<void>;
  subscribe(consumer: (job: EmailInput) => Promise<void>): void;
  close(): Promise<void>;
}

Redis-backed queue using LPUSH (producer) + RPOP (consumer poll) on a dedicated redis client (the redis package). Jobs are JSON-serialized EmailInputs. ensureConnected() lazily creates and connects the client on first push; the poller calls it indirectly. Transient redis errors during drain are swallowed so the poller survives. Callers that need guaranteed delivery should check connectivity at boot — push will throw if connect() fails.

MemberDescription
constructor(createClient, key?, pollMs?)createClient returns a redis client (factory for lazy connect); key defaults to 'nexus:email:queue'; poller defaults to 100 ms.
ensureConnected()Create + connect() the client on first use; no-op once connected.
push(job)LPUSH the JSON-serialized job (connects first).
subscribe(consumer)Register an async consumer; called per RPOP'd job during drain.
close()Clear the poller interval and quit() the client if connected.

Service — EmailService

class EmailService {
  readonly provider: EmailProvider;
  constructor(opts: EmailServiceOptions);
  send(input: EmailInput): Promise<EmailResult>;
  queue(input: EmailInput): Promise<void>;
  startWorker(): void;
  close(): Promise<void>;
}

Ties a provider + template engine + optional queue together. send() renders (if a template is named) and sends immediately. queue() renders then enqueues for background delivery; startWorker() subscribes the service to the queue so jobs are drained with retries. close() stops the worker and closes the queue backend.

EmailServiceOptions

FieldTypeDefaultDescription
providerEmailProvider—Required transport.
templates?TemplateEngine—Engine used to render named templates / subject tokens.
queue?QueueBackend—Optional queue; when set, queue() enqueues and a worker drains it.
maxAttempts?number3Max send attempts per queued job (exponential backoff).
MethodDescription
send(input)Render via the template engine (if set) then call provider.send(); returns the EmailResult.
queue(input)Render then queueBackend.push(). Throws '[nexus-email] no queue configured' if no queue was supplied.
startWorker()Idempotent. Subscribes processWithRetry to the queue backend so queued jobs are drained with retry/backoff. No-op if no queue or already running.
close()Stop the worker (running = false) and close the queue backend (if any).

processWithRetry(job) — private

private async processWithRetry(job: EmailInput): Promise<void>

Internal worker handler subscribed by startWorker(). Sends the (already rendered) job up to maxAttempts times. On failure it waits with exponential backoff 250 * 2 ** (attempt - 1) ms (attempt is 1-indexed after the first failure: 250, 500, 1000, 2000, …) before the next attempt. After maxAttempts failures it gives up and logs '[nexus-email] delivery failed after <n> attempts: <err>' — in production route these to a dead-letter store.

// backoff sequence (maxAttempts = 3): attempt 1 fails → wait 250ms → attempt 2 fails → wait 500ms → attempt 3 fails → give up + log
Retry lives in the service MemoryQueue / RedisQueue only push + subscribe + drain. Exponential backoff and maxAttempts are EmailService behavior — that's why a queue backend with no EmailService worker will not retry.
Render-then-enqueue queue() renders the template before pushing, so the worker sends already-rendered EmailInputs. The worker does not re-render — don't put raw template tokens in a queued job expecting them to resolve on send.

Usage

import { createEmail, TemplateEngine, MemoryQueue } from '@bhooai/nexus-email';

const templates = new TemplateEngine();
templates.register('welcome', '<h1>Welcome, {{name}}!</h1><p>Verify {{email}}.</p>');

const email = createEmail(config.email, { templates, queue: new MemoryQueue() });
email.startWorker();

// synchronous send (renders template, returns EmailResult)
await email.send({ to: 'ravi@x.com', subject: 'Welcome {{name}}', template: 'welcome', vars: { name: 'Ravi', email: 'ravi@x.com' } });

// background send (renders, enqueues; retried up to maxAttempts on failure)
await email.queue({ to: 'maya@x.com', subject: 'Receipt', template: 'welcome', vars: { name: 'Maya', email: 'maya@x.com' } });

await email.close();
Dev provider In development, LogProvider prints the rendered email instead of sending — no SMTP server needed. Tests use jsonTransport; no network.

API Reference

Supervisor API Localhost-only control API on port 7474 that the nexus dev supervisor exposes to the admin app.

The Supervisor from @bhooai/nexus-cli owns the four child processes (backend, frontend, AI, admin), streams prefixed colored logs, keeps a per-service ring buffer, and exposes a tiny HTTP control API so the admin shell can drive it without coupling to OS-specific process management.

Binding & discovery

AspectDetail
Host127.0.0.1 only — never binds a public interface
Port7474 by default; auto-increments if already in use
AuthNone. The loopback binding is the security boundary.
CORSPermissive — allows the admin app (on :3001) to call it directly
DiscoveryThe main server writes supervisor.json (control URL/port) the admin app reads at boot
Loopback only The supervisor never binds 0.0.0.0. Anything that can reach 127.0.0.1:7474 can start/stop your services — do not forward the port, and do not run the supervisor inside a container whose loopback is shared with untrusted tenants.

Types

ServiceSpec

The input descriptor used to construct a Supervisor — one per supervised service. Exported from @bhooai/nexus-cli.

FieldTypeDescription
namestringService identifier (e.g. 'backend', 'frontend', 'ai', 'admin'). Used in status, logs, and the ?name= query params.
commandstring[]Command + args to run. Index 0 is the executable; the rest are its arguments. An empty/missing command marks the service 'errored' and emits a system log.
cwdstringWorking directory, relative to the project root passed to the constructor. Resolved with path.resolve(root, cwd).
colorstringANSI escape sequence used to color the log prefix (e.g. '\x1b[36m'). The [name] prefix and reset are applied by the supervisor.
optional?booleanWhen true, a start failure or non-zero exit is logged but the supervisor keeps running. When false/undefined, an exit emits a hint to run nexus dev restart <name> (the supervisor still continues — it does not crash).
env?Record<string, string>Extra environment variables merged on top of process.env for this child. The admin service additionally receives VITE_SUPERVISOR_URL pointing at the actually-bound control URL.

ServiceState

The runtime snapshot of one supervised service, returned by status() and the GET /status endpoint.

FieldTypeDescription
namestringService identifier.
status'stopped' | 'running' | 'errored'Current lifecycle state. 'stopped' is set by an intentional stop or during shutdown; 'errored' is set when a running process exits on its own (non-shutdown) or fails to start.
pid?numberChild process PID — present only while status === 'running'; cleared on exit.
startedAt?numberEpoch milliseconds of the last successful startService.
lastExitCode?number | nullExit code of the most recent run (null if the process was killed by a signal). Absent until the process has exited at least once.
logTailstring[]Rolling per-service log buffer (capped at MAX_TAIL = 200 entries, oldest dropped first).

LogEntry

Structured log entry returned by GET /logs/all. Each captured stdout/stderr line is classified into a level by detectLevel and timestamped.

FieldTypeDescription
servicestringName of the service that produced the line.
tsnumberEpoch milliseconds when the line was captured.
source'stdout' | 'stderr' | 'system'Origin stream. 'system' is used for supervisor-generated lines (start failures, exit notices, "no command specified").
level'info' | 'warn' | 'error'Severity, inferred from the line text (see detectLevel).
linestringThe raw log line (prefix and ANSI color are not included).

Supervisor class

The Supervisor class is exported from @bhooai/nexus-cli (packages/nexus-cli/src/supervisor.ts). It owns child processes, streams prefixed colored logs, handles graceful shutdown, and exposes a localhost HTTP control API for the admin app.

Constructor

new Supervisor(services: ServiceSpec[], root: string, controlPort = 7474)
ParameterTypeDefaultDescription
servicesServiceSpec[]—Service descriptors (one per child process). Each is seeded with a 'stopped' state and an empty logTail.
rootstring—Project root used to resolve each ServiceSpec.cwd and to write supervisor.json.
controlPortnumber7474Requested control API port. The actual bound port may differ — see auto-increment.

Properties

MemberTypeDescription
controlEndpointPort (getter)numberThe port the control API actually bound. 0 until start() has bound a socket; may be greater than the requested controlPort after auto-incrementing past a busy port. Read this (rather than the constructor argument) when you need the real URL.

Methods

MethodSignatureDescription
startService(spec: ServiceSpec): voidSpawn a service's command in spec.cwd (resolved against root), wire up stdout/stderr streaming + exit handling, and flip its state to 'running'. No-op if already running. An empty command[0] marks the service 'errored' and logs a system message. Prepends the local, project, and framework node_modules/.bin to PATH so tsx/vite resolve even when the supervisor is launched directly (not via npm run dev). On Windows, spawns with shell: true.
stopService(name: string): voidStop a running service. Sets state to 'stopped' first so the eventual exit handler doesn't relabel it 'errored'. Windows: taskkill /PID <pid> /T /F (kills the whole cmd.exe-spawned tree, since proc.kill() only terminates the wrapper). POSIX: signals the process group (process.kill(-pid, 'SIGTERM')) with a fallback to proc.kill('SIGTERM'). No-op if the service isn't running.
restartService(name: string): voidStop the service, wait 300ms, then start it again. No-op if name is not a known service.
status(): ServiceState[]Return a fresh array of every service's ServiceState (in constructor order). Each entry is a shallow copy, so callers can't mutate the supervisor's internal state.
start(): Promise<void>Bind the control API (see auto-increment), inject VITE_SUPERVISOR_URL into the admin service's env, start every service, and register SIGINT/SIGTERM handlers that call shutdown(). Resolves once the control server is bound and all services have been spawned.
shutdown(): Promise<void>Idempotent graceful shutdown. Sets an internal flag, calls stopService on every running process, closes the control HTTP server, waits 200ms for processes to exit, then calls process.exit(0). Safe to call multiple times — the second and later calls return immediately.

Binding behavior & port auto-increment

The control API binds 127.0.0.1 only. When the requested controlPort (default 7474) is already in use — e.g. another nexus dev is running — the supervisor does not fail. It auto-increments:

const MAX_ATTEMPTS = 100;
for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
  const port = requested + attempt;     // 7474, 7475, 7476, ...
  try { await tryListen(server, port); break; }
  catch (err) {
    if (err.code !== 'EADDRINUSE') break;  // give up on anything else
  }
}
  • On success, controlEndpointPort and the internal controlPort are updated to the actually-bound port, and a note is printed when it differs from the requested one.
  • The scan is capped at 100 attempts (so at most requested + 99). If no free port is found in that range, the supervisor prints an error and continues without a control API (controlEndpointPort stays 0); child services still run.
  • Any non-EADDRINUSE bind error also aborts the scan.

Once bound, the supervisor writes supervisor.json at the project root so the backend and admin app can discover the actual endpoint:

{
  "port": 7475,
  "url": "http://127.0.0.1:7475",   // omitted (undefined) if nothing bound
  "writtenAt": "2026-08-10T09:42:11.000Z"  // ISO timestamp
}

The admin service additionally receives VITE_SUPERVISOR_URL in its env, pointing at the real URL — so the admin app doesn't even need to read the JSON file.

Log level detection

Every captured line (stdout, stderr, or system) is classified into a level by the detectLevel(line) helper, which lowercases the line and matches word-boundary regexes:

LevelTriggers (case-insensitive, word-boundary)
'error'error, fatal, fail / failed / failure, exception
'warn'warn / warning, unauthorized, forbidden
'info'Everything else (the default).
 
function detectLevel(line: string): LogEntry['level'] {
  const lower = line.toLowerCase();
  if (/\berror\b/.test(lower) || /\bfatal\b/.test(lower)
      || /\bfail(ed|ure)?\b/.test(lower) || /\bexception\b/.test(lower)) return 'error';
  if (/\bwarn(ing)?\b/.test(lower) || /\bunauthorized\b/.test(lower)
      || /\bforbidden\b/.test(lower)) return 'warn';
  return 'info';
}
source ≠ level A line on stdout can still be classified 'error' (e.g. a Python traceback printed to stdout), and a line on stderr can be 'info'. The source field records the stream; level records the inferred severity — they're independent.

Log buffers

The supervisor keeps two rolling log buffers, both dropped-from-the-front (FIFO) ring buffers:

ConstantValueScopeFeeds
MAX_TAIL200Per service — each ServiceState.logTailGET /logs?name=
MAX_ALL_LOGS2000Aggregate — the single internal allLogs: LogEntry[]GET /logs/all

Both are exported as module constants from @bhooai/nexus-cli. Every captured line is pushed to both buffers: the per-service logTail stores the raw line, while allLogs stores the full structured LogEntry (with ts, source, and inferred level).

Endpoints

MethodPathResponseDescription
GET/status{ services: ServiceState[] }All supervised services and their current state
POST/start?name=<service>{ ok: boolean }Start a service
POST/stop?name=<service>{ ok: boolean }Stop a service (taskkill /T /F on Windows, process-group kill on Unix)
POST/restart?name=<service>{ ok: boolean }Restart — stop, wait 300ms, then start
GET/logs?name=<service>{ logs: string[] }Per-service log tail (last 200 lines)
GET/logs/all?service=&level=&q={ logs: LogEntry[] }Aggregated structured logs (last 2000 entries) with optional filtering
POST/logs/clear{ ok: true }Clear all log buffers

GET /logs/all filters

All three query params are optional and combine with AND semantics. Empty/absent means "no filter on that dimension".

ParamTypeBehavior
servicestringExact match against LogEntry.service (e.g. 'ai').
levelstringExact match against LogEntry.level — one of 'info' / 'warn' / 'error'.
qstringCase-insensitive substring search over LogEntry.line.
 
// errors from the AI service containing 'traceback'
const url = new URL('http://127.0.0.1:7474/logs/all');
url.searchParams.set('service', 'ai');
url.searchParams.set('level', 'error');
url.searchParams.set('q', 'traceback');
const { logs } = await fetch(url).then(r => r.json());

POST /logs/clear

Empties both buffers: every per-service logTail is reset to [] and the aggregate allLogs is reset to []. Always returns { ok: true }. The supervised processes themselves are unaffected — only the in-memory history is dropped.

Response shapes

ServiceState

{
  name: 'backend',                       // service identifier

  pid: 42871?,                         // present when running

  lastExitCode: 0?,                    // exit code of the last run (null if signal-killed)

{

Usage

// from the admin app (same machine)
const base = 'http://127.0.0.1:7474';

await fetch(`${base}/restart?name=backend`, { method: 'POST' });

const status = await fetch(`${base}/status`).then(r => r.json());
console.log(status.services);

// aggregated structured logs, filtered
const url = new URL(`${base}/logs/all`);
url.searchParams.set('service', 'ai');
url.searchParams.set('level', 'error');
url.searchParams.set('q', 'traceback');
const { logs } = await fetch(url).then(r => r.json());

Constructing a Supervisor directly

import { Supervisor } from '@bhooai/nexus-cli';

const supervisor = new Supervisor(
  [
    { name: 'backend',  command: ['tsx', 'apps/backend/src/main.ts'], cwd: '.', color: '\x1b[35m' },
    { name: 'frontend', command: ['vite', '--port', '3000'],         cwd: 'apps/frontend', color: '\x1b[36m' },
    { name: 'ai',       command: ['uvicorn', 'main:app'],            cwd: 'ai', color: '\x1b[33m', optional: true },
    { name: 'admin',    command: ['vite', '--port', '3001'],         cwd: 'apps/admin',    color: '\x1b[34m' },
  ],
  process.cwd(),   // root — used to resolve cwd and write supervisor.json
  7474,            // controlPort (optional, defaults to 7474)
);

await supervisor.start();
console.log('control API on port', supervisor.controlEndpointPort);  // may be > 7474

// ...later
supervisor.restartService('backend');
console.log(supervisor.status());

process.on('SIGINT', () => supervisor.shutdown());  // start() also wires this for you
Admin proxy The main backend exposes GET /admin/supervisor (JWT + admin) which returns the control URL/port from supervisor.json. The admin app talks to the supervisor directly over loopback — the backend never proxies the control calls.

Allow-listed commands

The supervisor itself does not parse or restrict the command it spawns — it runs exactly what the ServiceSpec declares. The allow-listing happens one layer up: the nexus dev launcher in @bhooai/nexus-cli builds the ServiceSpec[] from a fixed set of known service definitions (backend, frontend, AI, admin), so the only commands ever spawned are the framework's own tsx/vite/uvicorn launches. The HTTP control API can only start/stop/restart services that were passed to the constructor — it cannot spawn arbitrary commands.

@bhooai/admin Admin Client API The client the admin React app uses to call the backend.

These are the client-side functions the admin React app (apps/admin) uses to talk to the backend's /admin/* endpoints. They are not imported by user apps — they live in the @bhooai/admin package, whose single source file is packages/nexus-admin/src/api.ts. The matching server-side route handlers are registered by registerAdminRoutes in apps/backend/src/modules/admin/adminRoutes.ts.

The module keeps two pieces of module-level state: the current JWT access token (set after login, sent as Authorization: Bearer <token>) and the current CSRF token, which is re-fetched from /csrf-token before every mutating call (the server rotates the CSRF cookie on every safe request, so a cached token goes stale the moment any other GET runs). Credentials (cookies) are always sent.

Two transports Auth, config, plugins, users, metrics, preflight, lint, payments, databases, AI, and cluster calls go to the backend (same origin as the admin Vite app — proxied in dev). Process-control calls (services, logs) go to the supervisor control API (default http://localhost:7474), whose URL is resolved once via resolveSupervisor() from /admin/supervisor or the VITE_SUPERVISOR_URL env var.

Store the JWT access token used as Authorization: Bearer <token> on subsequent admin calls. login / registerAndLogin set this for you.

function getAccessToken(): string

login(email, password)

async function login(email: string, password: string): Promise<{ user: any; accessToken: string }>

Refresh the CSRF token, then POST /auth/login with { email, password }. On success stores the returned access token and returns { user, accessToken }. Throws a friendly, human-readable error message on any failure (network down, 401, 429, etc.).

registerAndLogin(email, password, name)

async function registerAndLogin(email: string, password: string, name: string): Promise<{ user: any; accessToken: string }>

Refresh the CSRF token, then POST /auth/register with { email, password, name }. On success stores the returned access token and returns { user, accessToken }. Throws a friendly error message on failure (e.g. 409 → "A user with that email already exists.").

Friendly errors Both auth helpers extract error.message from the JSON body, and fall back to status-specific copy (401 → "Invalid email or password.", 404 → "Auth endpoint not found — is the backend running?", 429 → "Too many attempts…", network failure → "Cannot reach the backend — is the server running?").

Supervisor client

These functions talk to the supervisor control API (a separate process), not the backend. The base URL is resolved once by resolveSupervisor().

async function resolveSupervisor(): Promise<string>

Resolve and cache the supervisor URL. Precedence: a cached value > VITE_SUPERVISOR_URL > /admin/supervisor (.url or .port) > fallback http://localhost:7474.

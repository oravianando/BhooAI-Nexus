API Reference

Node Agent API The control API that runs on every cluster node (default port 7575), driven by the central ClusterManager via Bearer auth.

The NodeAgent class is exported from @bhooai/nexus-cluster (it is also documented from the cluster side in Cluster API → NodeAgent). It runs on every node that participates in the cluster mesh. The central side (registry + load balancer + autoscaler) talks to each node's agent over a small HTTP API to discover identity, probe health, sample metrics, and execute lifecycle commands. The agent owns the node's role service as one child process and enforces a command allowlist.

Binding & auth

AspectDetail
Host0.0.0.0 by default at runtime (NodeAgent.listen() binds all interfaces so the central can reach it across hosts). The config default for cluster.nodeAgentHost is '127.0.0.1' — override either layer to lock down exposure.
Portcluster.nodeAgentPort — default 7575; pass --port=7576 to override per-node
AuthEvery route requires Authorization: Bearer <token> where the token matches cluster.token from nexus.config.ts (or a per-node slave-generated token). Missing/wrong token → 401.
RoleThe node's role (backend, files, database, or ai) is set with --role=<role> at serve time
Shared pairing secret The agent runs on cluster.nodeAgentPort (default 7575). Start it with nexus node serve --role=backend --port=7576. The Bearer token must match the cluster.token in nexus.config.ts — anyone holding that token can start/stop/update services on the node, so rotate it and keep it out of the repo.

Endpoints

MethodPathAuthResponseDescription
GET/infoBearerNodeIdentityNode identity — the registry stores this on a successful /admin/cluster/link
GET/healthBearerNodeHealthProbes the role service's /health endpoint (if a URL is advertised); reports true/false per role service
GET/metricsBearerNodeMetricsSampleCurrent metrics sample — feeds the autoscaler's scale-up/down decisions
POST/execBearerNodeExecResultExecute an allow-listed command: start / stop / restart / logs / update

Response shapes

/info (NodeIdentity)

{
  id: 'a1b2c3d4e5f6-backend',        // first 12 hex of sha256(root::role) + "-" + role
  role: 'backend',                     // 'backend' | 'files' | 'database' | 'ai'
  tier: 'standard',                    // 'dev' | 'standard' | 'large'
  version: '0.1.0',
  baseUrl: 'http://node-7:7575',        // agent control API URL (NOT the role service)
  services: {                            // role -> service base URL map
    backend: 'http://node-7:4000',
  },
  capabilities: ['start', 'stop', 'restart', 'logs', 'update', 'metrics']
}
services is a role→URL map services is a Partial<Record<NodeRole, string>> mapping each role this node serves to that service's base URL — not an array of role strings. The LB targets services.backend if present, else falls back to baseUrl.

/health (NodeHealth)

{
  ok: true,
  time: '2026-08-10T12:00:00.000Z',
  services: { backend: true },         // role -> boolean (only the node's own role)
  // message?: 'optional human-readable detail'  // not set by the inbuilt agent
}

/metrics (NodeMetricsSample)

{
  nodeId: 'a1b2c3d4e5f6-backend',
  rps: 12,                              // request count / uptime seconds (rounded up)
  cpu: 0,                               // always 0 — the agent does not measure CPU
  memoryMb: 482,                       // agent process RSS in MB
  sampledAt: 1715000000000                // epoch ms
}
cpu is always 0 The inbuilt agent hard-codes cpu: 0 in NodeMetricsSample — it never measures CPU. The field is kept for API compatibility with the autoscaler's cpuHigh rail, which therefore never triggers in practice. RPS-per-node is the effective scale signal.

/exec (NodeExecResult)

// request: NodeExecRequest
// { command: 'start' | 'stop' | 'restart' | 'logs' | 'update', target?, args? }
{
  ok: true,
  exitCode: null,                        // last child exit code, or null if running
  stdout: 'started npm run dev\n…',        // tail of the service log buffer (last ~200 lines)
  audit: 'run "start" by central at 2026-08-10T12:00:00.000Z'  // a STRING, not an array
  // stderr?: 'only present on rejected commands'
}

On a rejected command (ok: false, HTTP 400) the response includes stderr:

{
  ok: false,
  exitCode: 1,
  stdout: '',
  stderr: 'command "script" not allowed',
  audit: 'run "script" by central at 2026-08-10T12:00:00.000Z'
}

Usage

// node side — start this machine as part of the mesh
nexus node serve --role=backend --port=7576

// central side — register the node by its agent URL
nexus cluster link http://<node-host>:7576

// direct agent call (as the central does internally)
const token = config.cluster.token;
const h = { Authorization: `Bearer ${token}` };

const info = await fetch(`http://<node>:7576/info`, { headers: h }).then(r => r.json());
const metrics = await fetch(`http://<node>:7576/metrics`, { headers: h }).then(r => r.json());

await fetch(`http://<node>:7576/exec`, {
  method: 'POST', headers: { ...h, 'Content-Type': 'application/json' },
  body: JSON.stringify({ command: 'restart' }),
}).then(r => r.json());
Allow-listed commands only /exec accepts exactly start, stop, restart, logs, and update at runtime. Any other value is rejected with an error (HTTP 400) — there is no arbitrary shell escape hatch. update is an alias for restart — it calls restartService() and does not pull the latest code. The NodeCommand type also includes 'script', but the inbuilt agent rejects script at runtime; NodeExecRequest.target / args are accepted by the type but ignored by the allowlisted commands.

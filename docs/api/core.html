@bhooai/nexus-core Core API Config, DI, errors, and the inbuilt HTTP server.

The framework core. Everything else builds on it. No express — the HTTP server is custom on node:http with a trie router and a middleware pipeline.

Config — loaders

loadConfig(opts?)

async function loadConfig(opts?: LoadOptions): Promise<NexusConfig>

Load and merge configuration in precedence order, then validate with the zod schema and return a frozen, typed config. The precedence (low → high):

code defaults < framework default (nexus.config.ts) < user config
        < nexus.runtime.json < NEXUS_* env vars < CLI flags
const config = await loadConfig({
  root: process.cwd(),
  userConfigPath: './nexus.config.ts',   // optional — auto-imported if omitted
  defaultConfigPath: './nexus/nexus.config.ts', // optional framework base layer
  runtimePath: './nexus.runtime.json',   // optional — defaults to <root>/nexus.runtime.json
  env: process.env,                       // optional override (tests)
  cli: { server: { port: 5000 } },        // optional — highest precedence
});
config.server.port; config.db.uri; config.graphql.path;
Frozen The returned object is Object.freezed. Mutate by writing nexus.runtime.json (admin write-back) or setting NEXUS_* env vars.

loadConfigAuto(opts?)

async function loadConfigAuto(
  opts?: Omit<LoadOptions, 'userConfig' | 'userConfigPath' | 'defaultConfigPath'>
): Promise<NexusConfig>

Auto-discover and load config with the framework's two-level model — this is what apps/backend/src/main.ts and the CLI use. It locates the framework's shipped default (nexus/nexus.config.ts) via frameworkDefaultConfigPath() and the nearest user nexus.config.{ts,js,mjs,cjs} walking up from root via discoverUserConfigPath(), skipping the default path so the framework's own example config doesn't shadow a user-editable one at the project root.

const config = await loadConfigAuto({ root: process.cwd() });
//   = defaults < framework default < user config < runtime.json < env < cli
When to use which Use loadConfigAuto for app boot (it discovers config for you). Use loadConfig in tests or when you already have the user config object in hand and want explicit control over every layer.

mergeConfig(...sources)

function mergeConfig(...sources: DeepPartial<NexusConfig>[]): NexusConfig

Read-only accessor for tests/bootstrap that don't need file loading. Deep-merges the given sources over the code defaults, validates with the zod schema, and returns a frozen config.

const cfg = mergeConfig({ server: { port: 5000 } }, { graphql: { introspection: false } });

Config — environment

configFromEnv(env?)

function configFromEnv(env: NodeJS.ProcessEnv = process.env): DeepPartial<NexusConfig>

Build a config-override object from NEXUS_* environment variables. Nested keys use _ as a separator: NEXUS_SERVER_PORT → { server: { port } }.

Type coercion is applied: integers for numeric fields, booleans for true/false, otherwise strings. Known two-segment compounds collapse into a single camelCase key so that, for example, NEXUS_PAYMENTS_RAZORPAY_KEY_ID maps to payments.razorpay.keyId (not payments.razorpay.key.id).

loadEnvFile(root, env)

function loadEnvFile(root: string, env: NodeJS.ProcessEnv): void

Load <root>/.env into the given env object without overriding variables that are already set (a real environment value always wins). Dependency-free: parses KEY=VALUE (optional export prefix), # comments, blank lines, and optional single/double quotes.

loadConfig calls this for you when opts.env is not passed. Call it directly only if you need .env loaded outside the config flow (e.g. a CLI that reads secrets before the config stack is built). Double-loading is harmless — it's idempotent.

Config — helpers

resolvePath(cfg, rel)

function resolvePath(cfg: NexusConfig, rel: string): string

Resolve a path. (Currently resolves against process.cwd(); accepts a config for API symmetry with future root-aware resolution.)

frameworkDefaultConfigPath()

function frameworkDefaultConfigPath(): string

Path to the framework's own shipped nexus.config.ts, resolved relative to this module so it works both via tsx (src) and compiled (dist). When @bhooai/nexus-core is installed inside a user app's node_modules/, this resolves to a non-existent path — it is then simply skipped (a user app does not inherit the framework's example config).

discoverUserConfigPath(root, exclude?)

function discoverUserConfigPath(root: string, exclude?: string): string | undefined

First nexus.config.{ts,js,mjs,cjs} found walking up from root, skipping exclude. Stops at the filesystem root. Used by loadConfigAuto to find the user config while skipping the framework default.

Config — merge & validate

deepMerge(base, ...sources)

function deepMerge<T>(base: T, ...sources: unknown[]): T

Deep merge of plain objects. Later sources win. Arrays are replaced, not concatenated (config arrays are declarative). Non-plain objects (e.g. Date, RegExp) are assigned by reference. undefined values in sources are skipped.

isPlainObject(v)

function isPlainObject(v: unknown): v is Record<string, unknown>

True if v is a plain object (prototype is Object.prototype or null). Used by deepMerge to decide between recursive merge and reference assignment.

nexusConfigSchema

const nexusConfigSchema: z.ZodObject<...>

Zod validation schema for the merged NexusConfig. Validates types and the most error-prone fields (ports, URLs, TTLs, JWT secret length ≥ 8). Provider sub-configs use a permissive record so custom keys flow through. loadConfig and mergeConfig both .parse() through this schema before returning.

import { nexusConfigSchema } from '@bhooai/nexus-core';
const parsed = nexusConfigSchema.parse(maybeConfig);

defaults

const defaults: NexusConfig

The code-level defaults — the lowest-precedence layer of the config stack. Every field is present so a config that supplies nothing still boots. See the Config types section for the per-field defaults.

HTTP — router & server

Router

class Router {
  use(mw: Middleware): this;
  use(path: string, mw: Middleware): this;
  get(path: string, handler: Handler, mw: Middleware[] = []): this;
  post(path: string, handler: Handler, mw: Middleware[] = []): this;
  put / patch / delete / head / options(...): this;
  add(method: string, path: string, handler: Handler, mw: Middleware[] = []): this;
  match(method: string, path: string): { handler; params; middleware; pattern } | null;
  routes(): Array<{ method: string; path: string }>;
  get size(): number;
}

Trie router supporting static segments, :param segments (on ctx.params), and * wildcards. Per-route middleware runs before the handler; router-level middleware (via use) runs for all matched routes under its mount path. Unknown methods on a known path return 405 (with an allow header).

const router = new Router();
router.get('/health', (ctx) => ctx.json({ status: 'ok' }));
router.post('/users/:id/publish', handler, [authToken, requireRole('user')]);

// router-level middleware (global)
router.use(securityHeaders());
// ...or path-scoped
router.use('/admin', requireAdmin);

// introspection
router.routes(); // [{ method:'GET', path:'/health' }, ...]
router.size;      // number of registered routes
Signature router.method(path, handler, mw: Middleware[] = []) — middleware is the 3rd argument as an array, and runs before the handler.

NexusServer

class NexusServer {
  constructor(opts: ServerOptions);
  use(mw: Middleware): this;            // append middleware after construction
  listen(port: number, host?: string): Promise<void>;
  close(): Promise<void>;
  get address(): AddressInfo | string | null;
  get httpServer(): HttpServer;   // reuse for WS / subscriptions
}
const server = new NexusServer({
  router,
  bodyLimit: config.server.bodyLimit,
  middleware: [securityHeaders(), cors({...}), bodyParser(...), csrf(...), rateLimit(...)],
  trustProxy: config.server.trustProxy,
  certFile: config.server.certFile, keyFile: config.server.keyFile,
  onError: (err, ctx) => ({ error: { code: err.code, message: err.message } }),
});
await server.listen(config.server.port, config.server.host);
server.use(myExtraMiddleware); // also available post-construction
server.httpServer; // attach WS upgrades here
await server.close();

Middleware is the middleware array passed to the constructor (or appended via server.use()). There is no global app.use() semantics — middleware runs in the order it was added.

HTTP — body parsing & uploads

bodyParser(limit?)

function bodyParser(limit = 1024 * 1024): Middleware

Parses application/json, application/x-www-form-urlencoded, text/plain, and multipart/form-data. Multipart file uploads populate ctx.state.files with UploadedFile[]. The raw body buffer is preserved on ctx.state.__rawBody (needed for webhook signature verification). Skips GET/HEAD.

router.post('/webhook', webhookHandler, [bodyParser(config.server.bodyLimit)]);

readBody(req, limit)

function readBody(req: IncomingMessage, limit: number): Promise<Buffer>

Read the full request body into a Buffer, capped at limit bytes. Throws a NexusError (code: 'BODY_TOO_LARGE', status 413) if exceeded. Used by bodyParser; also useful for raw-body handlers.

parseUrlEncoded(input)

function parseUrlEncoded(input: string): Record<string, string | string[]>

Parse a urlencoded string into a record. Repeated keys become arrays. + is decoded to space.

Minimal multipart/form-data parser sufficient for file uploads. Used by bodyParser; also usable directly on a raw body buffer.

serveStatic(root, options?)

function serveStatic(root: string, options: { index?: string; prefix?: string } = {}): Middleware

Serve static files from root. Safe against path traversal. Serves index.html for directories. Only handles GET/HEAD. prefix strips that URL prefix before mapping to disk.

router.use(serveStatic(uploadsDir, { prefix: config.uploads.path }));

The default storage directory is uploads/, the upload endpoint is POST /uploads, and saved files are available as /uploads/<generated-name>. Uploads require the normal CSRF token when CSRF middleware is enabled. Do not expose arbitrary user filenames or disable MIME/size validation in production.

DI — Container

type Factory<T> = (container: Container, ...deps: unknown[]) => T | Promise<T>;
type Lifetime = 'singleton' | 'transient';

class Container {
  register<T>(id: string, factory: Factory<T>, options?: { lifetime?: Lifetime; deps?: readonly string[] }): this;
  instance<T>(id: string, value: T): this;
  has(id: string): boolean;
  resolve<T>(id: string): T;
  resolveAsync<T>(id: string): Promise<T>;
  child(): Container;
  clear(): void;
}

class ResolutionError extends Error {
  readonly serviceId: string;
}

A minimal inbuilt dependency-injection container. Supports factory-based registration (factories receive the container and any declared dependencies), singletons, transients, and an already-constructed instance registration. Detects circular dependencies. Intentionally small — this is the service backbone used by the framework and plugins.

const container = new Container();
container.register('db', (c) => connectDb(), { lifetime: 'singleton' });
container.register('userRepo', (c) => new UserRepo(c.resolve('db')), { deps: ['db'] });
container.instance('config', config);

const repo = container.resolve<UserRepo>('userRepo');     // sync
const async = await container.resolveAsync('thing'); // awaits an async factory

container.has('db'); // true
const child = container.child();   // inherits registrations/values, can override locally
container.clear();
Circular deps Resolving a service that transitively depends on itself throws a ResolutionError.

Errors

Throw a typed error from any handler/middleware; onError shapes the response. Every error carries a stable code (for programmatic handling) and a statusCode.

if (!body.email) throw new ValidationError('email is required');
if (!ctx.state.user) throw new AuthenticationError('login required');

function toNexusError(err: unknown): NexusError

Normalize an unknown thrown value into a NexusError. A NexusError passes through; an Error becomes a new NexusError(err.message); anything else becomes NexusError(String(err)). Used by NexusServer internally.

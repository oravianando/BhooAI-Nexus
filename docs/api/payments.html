@bhooai/nexus-payments Payments API One PaymentProvider interface, five gateways, signed webhooks.

One unified adapter interface over five payment gateways. App code is gateway-agnostic: pick a provider by name, call createOrder / capture / refund, and mount a single webhook route. Amounts are always expressed in major units (e.g. 10.50); each provider converts to its native representation (Razorpay paise, PayPal decimal string, etc.).

Providers

RazorpayfullyesREST orders + HMAC-SHA256 webhook verify. Amounts in paise (INR).

PayUhappy-pathnoHash-based flow: SHA-512 request + response hash. createOrder builds the checkout params; capture/refund/status are stubs.
Skrillhappy-pathnoQuick Checkout redirect URL + MD5 md5sig IPN verify. Capture/refund/status are stubs.
Payoneerhappy-pathnoHMAC-signed redirect; webhook verified with HMAC-SHA256 over the raw body. No public sandbox — verified structurally, not live. Capture/refund/status are stubs.

Usage

import { createPayments } from '@bhooai/nexus-payments';

const payments = createPayments(config.payments);

router.post('/payments/order', async (ctx) => {
  const { provider, amount, currency, reference, description } = ctx.body;
  const gateway = payments.get(provider);          // throws when disabled
  const order = await gateway.createOrder({ amount, currency, reference, description });
  ctx.json(order);
}, [authToken(auth, { cookieName: config.auth.cookieName, allowCookie: true })]);

// webhooks mount on a route that includes :provider (the default webhookPath already does)
router.post(config.payments.webhookPath, payments.webhookRouter((ev) => {
  log.info('payment event', { provider: ev.provider, event: ev.event, verified: ev.verified });
}).handler);
Webhook route must include :provider The WebhookRouter.handler reads ctx.params.provider to look up the provider, and returns 404 when it is missing. The default payments.webhookPath is '/payments/webhook/:provider' — keep the :provider param if you override it. A fixed string like '/payments/webhook' would 404 every request.
Testing The HttpTransport is injectable — pass a mock as the second arg to createPayments so tests never touch a live gateway: 
const payments = createPayments(config.payments, { transport: mockTransport });
Razorpay/PayPal exercise the transport on every call; PayU/Skrill/Payoneer compute hashes locally (no transport needed for createOrder / verifyWebhook).

createPayments(config, opts?)

function createPayments(
  config: {
    razorpay?: ProviderConfig;
    paypal?: ProviderConfig;
    payu?: ProviderConfig;
    skrill?: ProviderConfig;
    payoneer?: ProviderConfig;
  },
  opts?: PaymentsOptions,
): PaymentsService

Build the payments service from a payments config section. A provider activates when enabled: true or all of its credential keys are set — so adding keys (via config or NEXUS_PAYMENTS_* env) without flipping enabled still yields a working provider. The only way to keep a configured provider off is enabled: false with keys present. The second arg injects an HttpTransport (defaults to fetchTransport).

PaymentProvider interface

interface PaymentProvider {
  readonly name: string;
  createOrder(input: CreateOrderInput): Promise<Order>;
  capture(input: CaptureInput): Promise<Order>;
  refund(input: RefundInput): Promise<RefundResult>;
  getOrderStatus(orderId: string): Promise<Order>;
  verifyWebhook(input: WebhookVerifyInput): Promise<WebhookEvent>;
  testConnection?(): Promise<ConnectionTest>;
}

Every gateway adapter implements this. testConnection is optional — only Razorpay and PayPal implement a safe anonymous probe; PayU/Skrill/Payoneer omit it and the admin test console reports them as "configured — no public probe".

MethodDescription
createOrder(input)Create an order at the provider. Returns an Order (with paymentUrl for hosted-checkout providers).
capture(input)Capture an authorized payment. Razorpay/PayPal call the provider API; PayU/Skrill/Payoneer delegate to getOrderStatus.
refund(input)Refund a captured payment. Razorpay/PayPal call the provider API; PayU/Skrill/Payoneer return a placeholder.
getOrderStatus(orderId)Fetch the current order status. Razorpay/PayPal hit the API; PayU/Skrill/Payoneer return a placeholder.
verifyWebhook(input)Verify a webhook signature and parse the event. Returns { verified, event?, data?, provider? }.
testConnection?()Optional live probe that authenticates without moving money. Razorpay lists orders; PayPal exchanges an OAuth token.

Errors — PaymentError

class PaymentError extends Error {
  readonly code: string;
  readonly provider: string;
  readonly status?: number;
  readonly raw?: unknown;
  constructor(message: string, opts: { code: string; provider: string; status?: number; raw?: unknown });
}

Payment-domain error thrown by every provider. code is machine-readable ('HTTP_ERROR', 'AUTH', 'CONFIG', ...), provider names the gateway, status is the upstream HTTP status when applicable, and raw is the parsed provider response (for debugging). name is 'PaymentError'.

HTTP transport

HttpRequest / HttpResponse / HttpTransport

interface HttpRequest {
  method: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';
  url: string;
  headers?: Record<string, string>;
  body?: string;
}
interface HttpResponse {
  status: number;
  body: string;
  headers?: Record<string, string>;
}
type HttpTransport = (req: HttpRequest) => Promise<HttpResponse>;

The injectable HTTP seam. Providers accept any HttpTransport; tests pass a mock that returns canned HttpResponses and never touches the network. Inject it via createPayments(config, { transport: mockTransport }).

fetchTransport

const fetchTransport: HttpTransport

Default transport built on the global fetch (Node ≥ 18). Returns { status, body, headers } with lowercased header keys. Used unless you inject your own.

jsonRequest(transport, provider, req)

function jsonRequest(transport: HttpTransport, provider: string, req: HttpRequest): Promise<any>

Run a JSON request through transport, parse the JSON body, and throw a PaymentError (code: 'HTTP_ERROR', status = upstream status) on non-2xx. Returns the parsed JSON (or undefined for an empty body). Every Razorpay and PayPal call goes through this.

basicAuth(user, pass)

function basicAuth(user: string, pass: string): string

Build a Basic Authorization header value from user:pass ('Basic ' + base64(user:pass)). Used by Razorpay (key id/secret) and PayPal's OAuth2 token exchange (client id/secret).

Signatures

hmacSha256Hex(key, message)

function hmacSha256Hex(key: string | Buffer, message: string): string

HMAC-SHA256 hex digest. Used by Razorpay webhooks and Payoneer (request signing + webhook verify).

sha512Hex(message)

function sha512Hex(message: string): string

SHA-512 hex digest. Used by PayU for the request and response hashes (payuRequestHash / payuResponseHash).

md5Hex(message)

function md5Hex(message: string): string

MD5 hex digest. Used by Skrill for the Quick Checkout md5sig (uppercase, per Skrill's spec).

safeEqual(a, b)

function safeEqual(a: string, b: string): boolean

Constant-time string compare. Returns false immediately on length mismatch, then XORs each character. Used by every webhook verifier to compare the provided signature against the expected one without leaking via timing.

Webhooks — WebhookRouter

class WebhookRouter {
  constructor(providers: Map<string, PaymentProvider>, onEvent: (event: WebhookEvent) => Promise<void> | void);
  handler: Handler;
}

Returned by payments.webhookRouter(onEvent). Mount its handler on POST /payments/webhook/:provider. The handler reads ctx.params.provider, looks up the provider, and dispatches the raw body to verifyWebhook:

  • Unknown/missing provider → 404 { error: 'unknown provider: <name>' }.
  • Bad signature → 401 { error: 'signature verification failed' }.
  • Verified → calls onEvent(event), then 200 { ok: true }.
  • onEvent throws → still 200 { ok: false, error } so the gateway doesn't retry — the app should persist + retry internally.

The raw body is taken from ctx.state.__rawBody (set by bodyParser) when available, falling back to re-serializing ctx.body. Webhook routes should run after bodyParser but without auth/CSRF — the signature is the auth.

Provider classes

RazorpayProvider

class RazorpayProvider implements PaymentProvider {
  readonly name = 'razorpay';
  constructor(cfg: RazorpayConfig, transport: HttpTransport);
  createOrder(input): Promise<Order>;
  capture(input): Promise<Order>;
  refund(input): Promise<RefundResult>;
  getOrderStatus(orderId): Promise<Order>;
  verifyWebhook(input): Promise<WebhookEvent>;
  testConnection(): Promise<ConnectionTest>;
}

Full adapter. Uses basic-auth (keyId / keySecret) against https://api.razorpay.com/v1. Amounts converted to paise via toMinor (3-decimal currencies ×1000, 0-decimal ×1, else ×100). capture requires paymentId and resolves the order currency first for partial captures. Webhooks verified with hmacSha256Hex(webhookSecret, rawBody) against the x-razorpay-signature header. testConnection lists one order.

PayPalProvider

class PayPalProvider implements PaymentProvider {
  readonly name = 'paypal';
  constructor(cfg: PayPalConfig, transport: HttpTransport);
  createOrder(input): Promise<Order>;
  capture(input): Promise<Order>;
  refund(input): Promise<RefundResult>;
  getOrderStatus(orderId): Promise<Order>;
  verifyWebhook(input): Promise<WebhookEvent>;
  testConnection(): Promise<ConnectionTest>;
}

Full adapter against the Orders v2 API. Caches an OAuth2 client-credentials token with a 5-minute safety margin on expiry (Date.now() < expiresAt - 300_000). Base URL is api-m.sandbox.paypal.com or api-m.paypal.com per sandbox. Amounts formatted as 2-decimal strings (toFixed(2)). Webhooks verified via the /v1/notifications/verify-webhook-signature API (PayPal signs with a rotating certificate, so local HMAC isn't possible) — requires webhookId configured. testConnection exchanges an OAuth token.

PayUProvider

class PayUProvider implements PaymentProvider {
  readonly name = 'payu';
  constructor(cfg: PayUConfig, transport: HttpTransport);
  createOrder(input): Promise<Order>;
  capture(input): Promise<Order>;
  refund(input): Promise<RefundResult>;
  getOrderStatus(orderId): Promise<Order>;
  verifyWebhook(input): Promise<WebhookEvent>;
}

Happy-path adapter for PayU India's hash-based flow. createOrder builds the checkout params + SHA-512 request hash and returns the hosted-checkout URL as paymentUrl (with the POST params in raw for the client to submit). verifyWebhook recomputes the response hash over the form fields and compares in constant time. No testConnection.

payuRequestHash(key, salt, p)

function payuRequestHash(key: string, salt: string, p: {
  txnid: string; amount: string; productinfo: string; firstname: string; email: string; udf: string[];
}): string

Request hash = sha512(key|txnid|amount|productinfo|firstname|email|udf1..udf10|salt). Exported so callers can build the checkout form outside createOrder if needed.

payuResponseHash(key, salt, p)

function payuResponseHash(key: string, salt: string, p: {
  status: string; txnid: string; amount: string; productinfo: string; firstname: string; email: string; udf: string[];
}): string

Response hash = sha512(salt|status|udf10..udf1|email|firstname|productinfo|amount|txnid|key) — the reverse sequence of the request hash.

SkrillProvider

class SkrillProvider implements PaymentProvider {
  readonly name = 'skrill';
  constructor(cfg: SkrillConfig, transport: HttpTransport);
  createOrder(input): Promise<Order>;
  capture(input): Promise<Order>;
  refund(input): Promise<RefundResult>;

Happy-path adapter for Skrill Quick Checkout. createOrder builds the https://pay.skrill.com/?... redirect URL with payment params and returns it as paymentUrl. The status-report IPN is verified by recomputing md5sig = MD5(merchantEmail + secretWord + mb_transaction_id + amount + currency) (uppercase) and comparing in constant time. No testConnection.

PayoneerProvider

class PayoneerProvider implements PaymentProvider {
  readonly name = 'payoneer';
  constructor(cfg: PayoneerConfig, transport: HttpTransport);
  createOrder(input): Promise<Order>;
  capture(input): Promise<Order>;
  refund(input): Promise<RefundResult>;
  getOrderStatus(orderId): Promise<Order>;
  verifyWebhook(input): Promise<WebhookEvent>;
}

Happy-path adapter. createOrder builds a signed redirect URL: HMAC-SHA256(apiKey, canonicalQuery(params)) appended as signature, sent to https://api.sandbox.payoneer.com/checkout/<programId> (or live). Webhooks verified with hmacSha256Hex(webhookSecret, rawBody) against the x-payoneer-signature header. Payoneer has no public sandbox without a provisioned program, so this adapter is verified structurally — not against live calls. No testConnection.

PayoneerConfig

FieldTypeDescription
enabled / sandboxbooleanOn/off + sandbox (selects api.sandbox.payoneer.com vs api.payoneer.com).
programIdstringPayoneer program id (activates the provider).
apiKeystringAPI key used as the HMAC key for request signing.
webhookSecret?stringShared secret for webhook HMAC verification; verifyWebhook returns verified: false if unset.
Happy-path stubs (PayU / Skrill / Payoneer) For these three providers, capture delegates to getOrderStatus, refund returns a placeholder RefundResult (status: 'pending', with a raw.note explaining the v1 limitation), and getOrderStatus returns a placeholder Order (status: 'pending', raw.note: '... status via webhook (v1)'). The real status arrives via the webhook; refunds happen via the provider's merchant panel / partner API. Treat these results as "no-op succeeded" — do not rely on them for ledger truth. Razorpay and PayPal implement all four methods against their live APIs.

@bhooai/nexus-cache Cache API Redis wrapper, cache-aside, pub/sub, rate-limit backend.

A thin Redis-backed layer used across the framework for caching, rate limiting, and pub/sub. Built on the redis (node-redis v4) client. Redis is required — clients connect lazily on first use, and connection errors propagate to the caller.

A Redis-backed cache wrapper. Lazily creates and connects a node-redis v4 client on first use via ensureConnected(). All keys pass through key() to apply an optional namespace/prefix. Values are JSON-encoded on write and JSON-parsed on read, so pass plain JSON-serializable values (no Map, Date is serialized to a string, etc.).

import { Cache } from '@bhooai/nexus-cache';

const cache = new Cache({ url: 'redis://localhost:6379', keyPrefix: 'app:' });

// TTL is a number of seconds — not an options object.
await cache.set('k', 'v', 60);
const v = await cache.get<string>('k');   // 'v'
await cache.del('k');

// INCR a counter; the TTL is set on the first hit of a fresh window.
const hits = await cache.incr('hits', 60);   // → 1, key expires in 60s

// cache-aside: (name, ttlSeconds, loader) — read-through with a TTL.
const user = await cache.cacheAside(`user:${id}`, 60, async () => User.findById(id).lean());

// bulk-delete keys by glob (non-blocking SCAN + DEL).
const removed = await cache.flushPattern('session:*');

await cache.close();
Redis required The cache does not degrade to misses when the URL is unreachable. ensureConnected() rethrows connection errors on every call until a connection succeeds, so a misconfigured or down Redis propagates errors to the caller.

constructor(opts?)

new Cache(opts: CacheOptions = {})

Creates the wrapper and the underlying node-redis client (not yet connected — connection is lazy). Options shape:

FieldTypeDescription
url?stringRedis connection URL (e.g. 'redis://localhost:6379'). If omitted, the client uses its library default.
namespace?stringLogical namespace applied to all keys as a ${namespace}: prefix.
keyPrefix?stringExplicit key prefix; overrides namespace when provided.
connectTimeout?numberConnection timeout in milliseconds, passed to the redis client's socket options.

The effective prefix is opts.keyPrefix ?? (opts.namespace ? `${opts.namespace}:` : '').

ensureConnected()

async ensureConnected(): Promise<void>

Connect the underlying client if not already connected. Idempotent — concurrent callers share the same in-flight connect promise. On failure the promise is reset so a later call can retry, and the error is rethrown. Called automatically by every method below; call it directly only if you want to fail fast at boot.

key(name)

function key(name: string): string

Build the fully-prefixed Redis key for a logical name (${keyPrefix}${name}). flushPattern applies the prefix to the pattern the same way.

get(name)

async get<T>(name: string): Promise<T | undefined>

Returns the JSON-decoded value, or undefined on a miss or a Redis NULL. A JSON parse failure throws (the stored value is expected to be valid JSON written by set).

set(name, value, ttlSeconds?)

async set<T>(name: string, value: T, ttlSeconds?: number): Promise<void>

Set a JSON-encoded value. The optional third argument is a number of seconds for the TTL (passed to Redis as EX); omit it for a key with no expiry.

await cache.set('k', 'v', 60);   // expires in 60s
await cache.set('k', 'v');        // no expiry
TTL is a number The third argument is a number of seconds, not an options object. Pass 60, not { ttl: 60 }.

del(name)

async del(name: string): Promise<void>

Delete a key. No-op (to the caller) if the key does not exist.

incr(name, ttlSeconds?)

async incr(name: string, ttlSeconds?: number): Promise<number>

Atomically INCR a key. When ttlSeconds is supplied and the result becomes 1 (the first hit in a fresh window), the key is expired after ttlSeconds seconds — this is the fixed-window primitive RateLimiter is built on. Returns the post-increment integer.

const n = await cache.incr('reqs:ip:1.2.3.4', 60);
// n === 1 on the first call → key expires in 60s; subsequent calls return 2, 3, ...

exists(name)

async exists(name: string): Promise<boolean>

True if the key exists in Redis.

expire(name, ttlSeconds)

async expire(name: string, ttlSeconds: number): Promise<void>

Set an expiry (in seconds) on an existing key. No-op if the key is missing.

ttl(name)

async ttl(name: string): Promise<number>

Remaining TTL in seconds. Returns -1 if the key has no expiry, -2 if the key is missing (matching Redis semantics).

flushPattern(pattern)

async flushPattern(pattern: string): Promise<number>

Delete all keys matching a glob pattern using non-blocking SCAN + DEL in batches of 100. The configured keyPrefix is prepended to the pattern (so 'session:*' becomes 'app:session:*'). Returns the number of keys removed. Safe to run in production — it does not block the Redis server.

cacheAside(name, ttlSeconds, loader)

async cacheAside<T>(name: string, ttlSeconds: number, loader: () => Promise<T>): Promise<T>

Cache-aside / read-through helper. Returns the cached value if present; otherwise invokes loader, stores its result with ttlSeconds, and returns it. The second argument is the TTL in seconds; the third is the loader function.

const user = await cache.cacheAside(`user:${id}`, 60, async () => User.findById(id).lean());
No negative caching There is no negative caching in v1 — a loader that throws propagates the error to the caller and nothing is stored. Wire your own try/catch around cacheAside if you need to cache misses.

close()

async close(): Promise<void>

Disconnect the underlying client (QUIT) if open, and clear the cached connect promise so a later use reconnects. Safe to call multiple times.

RateLimiter

class RateLimiter {
  constructor(cache: Cache);
  check(key: string, rule: RateLimitRule): Promise<RateLimitResult>;
  consume(key: string, rule: RateLimitRule): Promise<RateLimitResult>;
}

A fixed-window counter rate limiter backed by Redis INCR through a Cache. Each call to check atomically increments a per-key counter and, on the first hit of a window, sets the window expiry. The counter is consumed regardless of whether the request is allowed — matching in-memory store semantics.

import { Cache, RateLimiter } from '@bhooai/nexus-cache';

const cache = new Cache({ url: process.env.NEXUS_REDIS_URL });
const limiter = new RateLimiter(cache);   // takes a Cache, not options

const rule = { windowSeconds: 60, max: 100 };
const r = await limiter.check(req.ip, rule);
if (!r.allowed) {
  ctx.status(429);
  ctx.setHeader('retry-after', String(r.retryAfter));
  ctx.json({ error: { code: 'RATE_LIMITED', ...r } });
  return;
}
// r.limit, r.remaining, r.resetAt also available
Constructor takes a Cache new RateLimiter(cache) takes a Cache instance, not a config object. The limiter shares the cache's Redis connection.

check(key, rule)

async check(key: string, rule: RateLimitRule): Promise<RateLimitResult>

Check (and consume) one unit against rule for key. Two arguments — the key and the rule. The Redis counter key is ${key}:rate. Uses the live TTL of the counter to compute resetAt (falling back to now + windowSeconds if the TTL is missing). Returns a RateLimitResult; the counter is already consumed by INCR, so an over-limit call still decrements the remaining quota.

consume(key, rule)

async consume(key: string, rule: RateLimitRule): Promise<RateLimitResult>

Alias of check; the counter is already consumed by INCR, so there is no separate "consume" step.

PubSub

class PubSub {
  constructor(cache: Cache);
  publish(channel: string, message: unknown): Promise<void>;
  subscribe(channel: string, handler: (msg: unknown) => void): Promise<() => Promise<void>>;
  close(): Promise<void>;
}

A Redis pub/sub helper. Uses the Cache's client for publishing and a separate, dedicated subscriber client (required by redis v4 — a client cannot publish and subscribe on the same connection) for subscriptions. Both clients are connected lazily. The subscriber is created with the same url / connectTimeout as the cache's publisher client.

import { Cache, PubSub } from '@bhooai/nexus-cache';

const cache = new Cache({ url: process.env.NEXUS_REDIS_URL });
const pubsub = new PubSub(cache);

const unsub = await pubsub.subscribe('events', (msg) => {
  console.log('got', msg);   // JSON-parsed payload
});
await pubsub.publish('events', { hello: 'world' });
await unsub();   // removes the handler; unsubscribes when the last one is gone

await pubsub.close();

constructor(cache)

new PubSub(cache: Cache)

Construct the helper around an existing Cache. The publisher is the cache's own client; a separate subscriber client is created (but not connected) here, reusing the cache's url / connectTimeout.

publish(channel, message)

async publish(channel: string, message: unknown): Promise<void>

Publish a JSON-encoded message to channel. Ensures the cache (publisher) client is connected first. message is JSON.stringify'd.

subscribe(channel, handler)

async subscribe(
  channel: string,
  handler: (msg: unknown) => void
): Promise<() => Promise<void>>

Subscribe to channel; handler is invoked with the JSON-parsed payload for each message. Multiple handlers per channel are supported. Returns an unsubscribe function that removes the handler and, when no handlers remain for the channel, unsubscribes from Redis. The payload is JSON-parsed; if parsing fails the raw message string is passed to the handler instead.

close()

async close(): Promise<void>

Close the dedicated subscriber client (QUIT) if open, and clear its cached connect promise. The publisher (cache) client is not touched — close the Cache separately.

@bhooai/nexus-cluster Cluster / Mesh API Multi-host container mesh: node agents, registry, load balancer, autoscaler.

The cluster package. A node agent runs on every machine that joins the mesh; the central side holds a registry of linked nodes, a round-robin load balancer, and an autoscaler with deterministic guardrails plus an optional AI advisor. Built on @bhooai/nexus-core's HTTP server, router, and DI container.

NodeRole

type NodeRole = 'backend' | 'files' | 'database' | 'ai'

The service profile a node advertises. Re-exported from @bhooai/nexus-core (it is also used by the ClusterConfig section). There is no frontend or graphql role — the mesh only load-balances backend nodes.

NodeTier

type NodeTier = 'dev' | 'standard' | 'large'

Hardware/compute tier hint reported by a node at register time. Informational — the LB and autoscaler do not currently branch on it.

NodeCommand

type NodeCommand = 'start' | 'stop' | 'restart' | 'logs' | 'update' | 'script'

Commands the central may send to a node's /exec. Note: script is part of the type but the inbuilt NodeAgent rejects it — only start, stop, restart, logs, and update are actually allowed. update is an alias for restart (it calls restartService() and does not pull the latest code).

NodeAgent class

class NodeAgent {
  readonly server: NexusServer;
  constructor(opts: AgentOptions);
  static auth(token: string): Middleware;
  startService(): void;
  restartService(): void;
  stopService(): void;
  listen(host?: string): Promise<void>;
  close(): Promise<void>;
  get identitySnapshot(): NodeIdentity;
  get status(): string;
}

The control API that lives on every cluster node (default port from cluster.nodeAgentPort, 7575). Owns the node's role service as one child process and exposes /health, /info, /exec, /metrics to an authenticated central. Uses the framework HTTP core so CORS, request ids, and error handling behave like the rest of the framework. See Node Agent API for the wire shapes.

nodeIdFor(root, role)

function nodeIdFor(root: string, role: NodeRole): string

Canonical stable node id — the first 12 hex chars of sha256(resolve(root) + '::' + role) followed by -<role> (e.g. a1b2c3d4e5f6-backend). Stable across restarts for the same project root + role, so re-linking the same node updates the existing registry entry rather than creating a duplicate.

NodeRegistry class

class NodeRegistry {
  constructor(opts: RegistryOptions);
  setToken(token: string): void;
  list(): RegistryNode[];
  get(id: string): RegistryNode | undefined;
  remove(id: string): boolean;
  link(agentUrl: string, overrideRole?: NodeRole, linkToken?: string): Promise<RegistryNode>;
  poll(id: string): Promise<RegistryNode | undefined>;
  clientFor(id: string): NodeClient | undefined;
  readyByRole(role: string): RegistryNode[];
}

The central's book of linked nodes, persisted to a JSON file (gitignored) so the mesh survives restarts. A node is "linked" when a trusted central handshakes /info and /health with the shared token, then persisted. A corrupt registry file is ignored — the registry starts empty rather than crashing boot.

LoadBalancer class

class LoadBalancer {
  constructor(opts: LoadBalancerOptions);
  rpsSnapshot(): Record<string, number>;
  handle(req: IncomingMessage, res: ServerResponse): Promise<void>;
  countersSnapshot(): Record<string, number>;
  listen(port: number, host = '0.0.0.0'): Promise<void>;
  close(): Promise<void>;
}

The central's reverse proxy on cluster.lbPort (default 8080). Round-robins incoming HTTP across every ready backend node in the registry (role === 'backend'), streaming the raw request/response (SSE, uploads, and regular JSON all pass through untouched). Stamps x-bhooai-node on the response so you can see which node served each request. Handles CORS preflight (204), appends x-forwarded-{for,proto,host}, and drops set-cookie headers from upstream (handled by the framework's cookie layer). Returns 503 when no backend node is registered and 502 on an upstream error.

Autoscaler class

class Autoscaler {
  constructor(deps: AutoscalerDeps, cfg: ClusterConfig['autoscale']);
  tick(): Promise<DeterministicDecision>;
  start(intervalMs = 10_000): void;
  stop(): void;
}

Samples the LB's RPS histogram and node metrics, then decides scale-up / scale-down. Two layers: (1) deterministic guardrails — RPS-per-node and CPU hysteresis, always active in auto mode; (2) an optional AI advisor whose proposal is only followed when it stays inside the [minNodes, maxNodes] rails. On AI failure / null / off-rail answers, the deterministic rules take over, so auto mode can never breach the hard limits. manual mode always holds.

HttpAiAdvisor class

class HttpAiAdvisor implements AiAdvisor {
  constructor(opts: AiAdvisorOptions);
  decide(input: AutoscaleInput): Promise<DeterministicDecision | null>;
}

The "AI manages it automatically" layer. Sends the observed cluster metrics to the BhooAI Nexus AI server and asks for a bounded scale action. If the AI errors or answers with anything other than scale-up / scale-down / hold, returns null and the caller's deterministic guardrails remain authoritative. The rail check ([minNodes, maxNodes]) happens in the Autoscaler, not here.

Config

Both sides read host/port/token from the cluster section of nexus.config.ts. See ClusterConfig in the Core API for the full field reference and ClusterAutoscaleConfig for the autoscaler sub-config. The config defaults for lbHost and nodeAgentHost are '127.0.0.1' (loopback) — safe for single-host dev. The runtime bind default for NodeAgent.listen() and LoadBalancer.listen() is '0.0.0.0' (all interfaces) so the central can reach nodes across hosts; override either layer to lock down exposure.

cluster: {
  enabled: true,
  failOpenSingleNode: true,
  // config defaults (loopback) — safe for single-host dev
  lbHost: '127.0.0.1', lbPort: 8080,
  nodeAgentHost: '127.0.0.1', nodeAgentPort: 7575,
  registryFile: 'cluster.runtime.json',
  token: '<shared pairing secret>',
  autoscale: { enabled: true, mode: 'auto', minNodes: 1, maxNodes: 4,
               cooldownMs: 60_000, cpuHigh: 80, rpsPerNodeHigh: 15, rpsPerNodeLow: 5 },
}
// at runtime, agent.listen() and lb.listen() bind 0.0.0.0 unless overridden

Flow

// node side — run this machine as part of the mesh
nexus node serve --role=backend --port=7575

// central side — hold the registry + LB + autoscaler
nexus cluster serve

// register a node by its agent URL (handshake + /info + /health)
nexus cluster link http://<node-host>:7575

// observe / control
nexus cluster status          // linked nodes + LB RPS
nexus cluster scale 3         // target exactly 3 backend nodes
nexus cluster start|stop|restart|kill <id>

Autoscaler

Every 10s (default) the Autoscaler samples the LB's RPS histogram and node metrics, then acts: scale up when per-node RPS > rpsPerNodeHigh or CPU > cpuHigh, scale down when per-node RPS < rpsPerNodeLow (never below minNodes, never above maxNodes). In auto mode an AI advisor may propose a move, which is only accepted when it stays inside the rails; any failure or off-rail answer falls back to the deterministic rules. Because NodeMetricsSample.cpu is always 0 in the inbuilt agent, the CPU rail never triggers in practice — RPS-per-node is the effective signal.

@bhooai/nexus-cli CLI API The nexus command, the supervisor, and the config-sync engine.

The developer-facing command line. It boots the four-process dev stack under an inbuilt supervisor, scaffolds new projects from templates, syncs every derived artifact back to the single nexus.config.* source of truth, and orchestrates the root/node mesh. No external process manager — the supervisor is a small node:http server with a CORS-enabled control API that the admin SPA drives directly.

run(cmd, args)

async function run(cmd: string, args: string[]): Promise<number>

Dispatch a CLI command and return its exit code. run is the bin shim's entrypoint: bin/nexus.js parses process.argv and calls run(cmd, args). It loads the project .env once (via loadDotEnv) so NEXUS_* keys reach both the config loader and the supervised child processes (they inherit process.env).

import { run } from '@bhooai/nexus-cli';
process.exitCode = await run('dev', ['--only', 'backend,ai-server']);

Unknown commands print Unknown command: <cmd> followed by the help text and return 1. help, --help, and -h print help and return 0.

doctor()

async function doctor(): Promise<number>

Verify the environment end-to-end and print a colored checklist. It checks, in order:

  • Runtime versions — node, npm (npm --version), python/python3, git --version.
  • Project files — package.json, nexus.config.{ts,js,mjs,cjs}, .env.
  • Project structure — 10 directories: apps/backend, apps/frontend, apps/admin, apps/ai-server, packages, bin, uploads, plugins, certs, logs (each must exist and be non-empty).
  • Dependencies installed — node_modules in root, apps/backend, apps/frontend, apps/admin (each must have ≥ 10 packages).
  • Disk usage — uploads/ and logs/ directory sizes (always ok).
  • Config load — loadConfigAuto resolves; reports env + server host:port.
  • Service reachability — TCP probe of MongoDB (parsed from db.uri), Redis (redis.url), and the AI server (ai.serverUrl).
  • Port conflicts — backend, frontend, and admin ports free on 127.0.0.1.
  • JWT pipeline — rejects the default change-me-please secret; when a real secret is set, signs and verifies a live HS256 test token (jose) and checks the sub/roles payload round-trips.
  • Paths & flags — graphql.path/federation, ws.path/ws.requireCsrf, frontend.enabled, admin.enabled, cluster.enabled (+ LB port when on), payments.currency, email.provider.

A small set of names (node, config, jwt-secret, jwt token, package.json, nexus.config) are treated as critical — a failure there flips the summary to "Critical issues found — cannot start." Everything else is a warning. Regardless of outcome, doctor always returns 0 — it is advisory and never blocks boot.

init(opts?, args?)

async function init(opts?: InitOptions, args: string[] = []): Promise<number>

interface InitOptions {
  force?: boolean;
  target?: string;
}

Scaffold a new project from packages/nexus-cli/templates/ into target (defaults to .). opts.force / --force overwrites existing files; otherwise existing files are skipped (an existing package.json is deep-merged rather than clobbered). gitignore/dockerignore ship un-dotted in the template (npm strips dotfiles from tarballs) and are restored to .gitignore/ .dockerignore on copy.

Interactive wizard (TTY)

When process.stdin.isTTY and --no-interactive is not set, init runs a 20-step interactive wizard that leaves the project fully bootable after a single command:

  1. Banner — "BhooAI Nexus — project setup wizard" + what it will do.
  2. Prerequisite scan — node, npm, python, git versions; Mongo + Redis TCP reachability with a retry/continue/abort prompt.
  3. Project name → stamped into package.json name.
  4. Server kind — root (mesh hub) or node (worker).
  5. Cluster role + port (node only) — backend / ai / files / database + agent port.
  6. Ports — auto-allocate free ports for backend/frontend/admin/ai.
  7. Mongo URI — confirm or edit (default mongodb://localhost:27017/<name>).
  8. Redis URL — confirm or edit (default redis://localhost:6379).
  9. AI providers — multi-select (Ollama/OpenAI/Anthropic/…); per-key prompt for each.
  10. Python venv — create .venv for the AI server? (default yes).
  11. Review summary — table of all choices; proceed?
  12. Scaffold — copy template files.
  13. Wire framework — patch workspace paths + file: dep + Vite/Tailwind.
  14. Allocate ports — auto-pick free ports (walks up to 100 ports from defaults).
  15. Write config — patch nexus.config.ts with chosen Mongo URI / Redis URL, stamp cluster.enabled + token (fresh token for root; reuse sibling-root token for node), patch package.json name.
  16. Generate .env — JWT secret + MONGODB_URI + REDIS_URL + AI_HOST=127.0.0.1 + AI keys + payment placeholders.
  17. Register project — upsert record into nexus_projects.projects (name, path, dbName, status='stopped', settings snapshot). Non-fatal if Mongo is unreachable.
  18. npm install — skip with --skip-install.
  19. Python setup — call pysetup to install AI-server deps.
  20. Verify + next steps — run mini-doctor on the new project; print onboarding URLs.

In non-interactive mode (CI, or --no-interactive), all values are taken from flags with sensible defaults.

FlagDescription
--forceOverwrite existing files (also settable via opts.force).
--as=root|nodeServer kind — hub of the mesh (root, default) or a worker that joins a root (node).
--name=NProject name → package.json name + MongoDB db name. Default: target directory basename.
--mongo-uri=URIMongoDB connection string (default mongodb://localhost:27017/<name>).
--redis-url=URLRedis connection string (default redis://localhost:6379).
--ai-providers=a,bComma-separated AI providers to enable (default ollama).
--ai-key id=valSet an AI provider API key (repeatable). Keys go into .env.
--cluster-token=TShared cluster pairing token (node mode — reuse the root's token).
--role=<R>Node role: backend (default), files, database, or ai.
--port=<N>Node agent port (default 7575).
--venv / --no-venvCreate Python virtualenv for the AI server (--venv is the default in interactive mode).
--no-interactiveRun fully non-interactively (CI-safe); all values from flags + defaults.
--skip-installSkip both npm install and pysetup.
--skip-mongo-checkSkip the Mongo/Redis TCP reachability check in step 1.

Usage examples

// Quick interactive wizard
nexus init my-app

// Scaffold a node that pairs with a sibling root
// (the wizard auto-detects the root's cluster token)
nexus init slave-1 --as=node --role=backend --port=7575

// CI one-liner (non-interactive, all flags)
nexus init ci-app --no-interactive --name ci-app \
  --mongo-uri mongodb://localhost:27017/ci-app \
  --ai-providers ollama --venv --skip-install

// Re-run in an existing project (idempotent — only updates config + .env)
nexus init . --no-interactive --name updated-name

// Skip Mongo/Redis probes for cloud environments
nexus init cloud-app --skip-mongo-check \
  --mongo-uri "mongodb+srv://user:pass@cluster.mongodb.net/db"

uninstall(args)

async function uninstall(args: string[]): Promise<number>

Remove a project and its databases. Resolves the project identity from package.json at the target, loads its config, and performs up to three actions:

  1. Drop the project's MongoDB database (e.g. test_app) — uses the project-info connection's MongoClient so no second connection is needed. Skipped with --keep-db or if Mongo is unreachable.
  2. Delete the project's record from nexus_projects.projects.
  3. Remove the project directory from disk — only with --purge. Handles Windows EPERM errors on read-only files (node_modules/.bin, .venv) by recursively clearing the read-only attribute, retrying up to 3× with backoff, and falling back to the OS shell (cmd /c rd /s /q on Windows, rm -rf elsewhere).
FlagDescription
--target <path>Project root (default: current directory).
--purgeAlso delete the project directory from disk after DB+record cleanup.
--forceSkip confirmation prompts.
--dry-runShow what would be deleted — nothing is changed.
--keep-dbDo not drop the project's database (only delete the record).
--no-interactiveNever prompt (refuses to run unless --force is also set).

Refuses to run non-interactively without --force. The nexus_projects database is never touched. Returns 0 on success, 1 if the target is not a nexus project or the operation was cancelled by the user.

dev(args?)

async function dev(args: string[] = []): Promise<number>

Load the effective config, optionally re-sync derived artifacts, then start the four services under a Supervisor:

  • backend — tsx watch apps/backend/src/main.ts;
  • frontend — vite --port <cfg.frontend.port> --host <cfg.frontend.host> (optional, dropped when frontend.enabled is false);
  • ai-server — python main.py in apps/ai-server with AI_PORT from ai.serverUrl (optional);
  • admin — vite --port <cfg.admin.port> --host <cfg.admin.host> (optional, dropped when admin.enabled is false).
FlagDescription
--only a,bStart only the named services (overrides enabled flags).
--no-syncSkip the pre-boot config re-sync even when the fingerprint has drifted.
--control-port <N>Control API base port (default 7474; auto-increments on EADDRINUSE).

dev prints a startup banner (service / host / port table), constructs the Supervisor with controlPort, calls supervisor.start(), prints quick-start URLs after 2s, and returns 0 — the supervisor keeps the process alive and handles SIGINT/SIGTERM.

pysetup(args)

async function pysetup(args: string[]): Promise<number>

Install the Python AI-server dependencies. Locates apps/ai-server/requirements.txt (or apps/server/requirements.txt / ./requirements.txt as fallbacks), optionally creates a virtualenv, and streams pip output through so progress is visible. Positional non-flag args are extra packages installed alongside the requirements file.

FlagDescription
--python <path>Path to a specific Python interpreter (else probes python/py on Windows, python3/python elsewhere).
--requirements <path> / -r <path>Use this requirements file instead of the auto-discovered one.
--upgrade / -UPass --upgrade to pip.
--venvCreate <requirementsDir>/.venv (if absent) and install into it; the venv's python is used for pip.
--interactivePrompt for venv y/n + python path when TTY (used internally by nexus init).

Returns the pip exit code; 1 if no requirements file or Python interpreter is found.

cluster(args)

async function cluster(args: string[]): Promise<number>

Central-side mesh orchestration. Loads the config, warns if cluster.enabled is false, and constructs a ClusterManager bound to cfg.cluster. The first positional arg is the subcommand:

SubcommandAction
statusList linked nodes (id, role, tier, status, enabled, rps, cpu/mem if metrics exist).
link <agent-url>Handshake + register a node by its agent URL. Returns 1 on failure.
unlink <id>Forget a node. 1 if no such node.
start <id> · stop <id> · restart <id> · kill <id>Run the named action on the node's agent (kill maps to stop). 1 without an id.
scale <n>Target exactly n backend nodes via manager.scaleTo.
serveHold the process: bind the LB on cluster.lbHost:lbPort, start the autoscaler (10s tick), and poll all nodes every 15s.
checkPoll every node once (health + metrics) and print the count.
help / (none)Print usage and return 0.

node(args)

async function node(args: string[]): Promise<number>

Run THIS machine as a cluster node. Loads the config, reads cluster.token and cluster.nodeAgentHost/nodeAgentPort, and dispatches on the first arg:

SubcommandAction
id --role <R> Print this node's stable id (nodeIdFor(cwd, role)) and return 0.
serve --role=<R> [--port <N>] Start a NodeAgent on cluster.nodeAgentHost:port (default cfg.cluster.nodeAgentPort → 7575), print the agent URL + pairing token, start the role service (tsx apps/backend/src/main.ts for backend/files/database; python main.py for ai), and hold the process (returns a never-resolving promise). NEXUS_NODE_ADVERTISED_URL overrides the advertised URL. Roles: backend, files, database, ai.
(none / unknown)Print usage and return 1.

syncCommand(args?)

async function syncCommand(args: string[] = []): Promise<number>

CLI wrapper around syncConfig. Loads the config, runs the sync with { write: !--check && !--dry-run, db: !--no-db }, prints a per-value summary table + per-file status table + db outcome + fingerprint, and returns 0. Flags: --check or --dry-run (audit only, nothing written), --no-db (skip the MongoDB upsert).

Templates

packages/nexus-cli/templates/ holds the real project files copied by init — a runnable backend (boots NexusServer with the security stack + /health, /csrf-token, /echo, and CSRF-protected /uploads), a React+Vite frontend with an upload example, a Python FastAPI AI server, an admin shell, and the bin/nexus.js CLI shim. The scaffold includes an ignored project-local uploads/ directory.

Config-sync engine

The sync layer propagates the single nexus.config.* source of truth into every derived artifact that still hardcodes a host/port/URL: the Dockerfile, docker.ps1/.sh/.bat helpers, bin/serve-all.mjs, apps/admin/package.json (the vite --port NNNN dev script), and the shared nexus_projects MongoDB record. A .nexus-sync.json fingerprint at the project root lets dev detect "config changed since last sync" and re-sync before booting.

syncConfig(root, cfg, opts?)

async function syncConfig(
  root: string,
  cfg: NexusConfig,
  opts?: SyncOptions,
): Promise<SyncReport>

interface SyncOptions {
  /** Write files (default true). False = dry-run / diff-only audit. */
  write?: boolean;
  /** Upsert the project-info MongoDB record (default true). */
  db?: boolean;
}

interface SyncReport {
  values: SyncValues;
  fingerprint: string;
  files: FileSyncReport[];
  db: 'updated' | 'skipped' | 'failed';
}

Render every derived file (Dockerfile, bin/serve-all.mjs, apps/admin/package.json, docker.ps1, docker.sh, docker.bat) against deriveValues(cfg, image). Missing files are reported as missing; unchanged files as in-sync; changed files as updated with a per-line diff. With opts.write !== false the new content is written and the fingerprint record is persisted to .nexus-sync.json. The DB upsert runs unless opts.db === false; a MongoDB failure is reported as failed (the sync still succeeds for files).

import { syncConfig } from '@bhooai/nexus-cli';
const report = await syncConfig(process.cwd(), cfg, { write: false });
report.files.filter((f) => f.status === 'updated');   // audit only

configChangedSinceSync(root, cfg)

function configChangedSinceSync(root: string, cfg: NexusConfig): boolean

True when no .nexus-sync.json exists yet, or when the stored fingerprint differs from the current one. dev calls this to decide whether to re-sync before booting.

Supervisor

class Supervisor {
  constructor(services: ServiceSpec[], root: string, controlPort = 7474);
  get controlEndpointPort(): number;   // 0 until start() binds
  startService(spec: ServiceSpec): void;
  stopService(name: string): void;
  restartService(name: string): void;
  status(): ServiceState[];
  start(): Promise<void>;
  shutdown(): Promise<void>;
}

The inbuilt process supervisor for the four Nexus terminals. It owns the child processes, streams prefixed colored logs (splitting on both CRLF and LF so Vite/uvicorn LF-only output flushes correctly), keeps a per-service log ring buffer (MAX_TAIL=200) plus an aggregated structured log buffer (MAX_ALL_LOGS=2000) powering /logs/all, handles graceful Ctrl-C, and exposes a localhost HTTP control API.

Each service is spawned with local + framework node_modules/.bin prepended to PATH so tsx/vite resolve even when the supervisor is launched directly via node bin/nexus.js dev (where npm hasn't prepended .bin). On Windows, children spawn with shell: true and stopService uses taskkill /T /F to kill the whole process tree (POSIX signals the process group) — so stop actually frees the port.

Port auto-allocation The control API does not fix itself to 7474. On EADDRINUSE (e.g. another nexus dev is already running) it auto-increments the port, up to 100 attempts, and the actual bound port is exposed via the controlEndpointPort getter and written to supervisor.json at the project root ({ port, url, writtenAt }) so the backend/admin can discover it. dev also injects VITE_SUPERVISOR_URL=http://127.0.0.1:<boundPort> into the admin service's env.

LogEntry

interface LogEntry {
  service: string;
  ts: number;                       // Date.now() ms
  source: 'stdout' | 'stderr' | 'system';
  level: 'info' | 'warn' | 'error';   // auto-classified from line content
  line: string;
}

Structured log entry returned by /logs/all. source is the originating stream (or system for supervisor-emitted lines like exit notices); level is auto-classified by scanning the lowercased line for error/fatal/fail/exception (error) and warn/unauthorized/forbidden (warn), defaulting to info.

Control API

The supervisor's HTTP control API is CORS-enabled (* origin) so the browser-based admin app (on :3001) can drive it directly — decoupling admin from OS-specific process management. Bound on 127.0.0.1 at controlPort (auto-allocated on collision):

EndpointMethodAction
/statusGETAll services + their ServiceState.
/start?name=<service>POSTStart a service.
/restart?name=<service>POSTRestart a service (stop + 300ms gap + start).
/stop?name=<service>POSTStop a complete service process tree (taskkill /T /F on Windows).
/logs?name=<service>GETTail a service's buffered logs (logTail, last MAX_TAIL=200).
/logs/all?service=&level=&q=GETAggregated structured logs across all services (LogEntry[], capped at MAX_ALL_LOGS=2000). Optional service, level, and q (case-insensitive substring) filters.
/logs/clearPOSTClear every service's logTail and the aggregated buffer.

Unknown paths return 404 with { error: 'not found' }. OPTIONS requests get a 204 (CORS preflight).

Programmatic use

import {
  run, doctor, init, dev, pysetup, uninstall, cluster, node, syncCommand,
  syncConfig, configChangedSinceSync, deriveValues, fingerprintOf,
  Supervisor,
  type LogEntry,
} from '@bhooai/nexus-cli';

// CLI dispatch — load .env, then run a command (returns exit code).
await run('doctor', []);

// Run a command function directly (skips the .env load + arg parsing).
await dev(['--only', 'backend', '--control-port', '7480']);

// Audit derived artifacts without writing.
const cfg = await loadConfigAuto({ root: process.cwd() });
if (configChangedSinceSync(process.cwd(), cfg)) {
  const report = await syncConfig(process.cwd(), cfg, { write: false });
  console.log(report.fingerprint, report.files.filter((f) => f.status === 'updated'));
}

// Stand up a supervisor over an arbitrary service set.
const supervisor = new Supervisor(
  [{ name: 'api', command: ['node', 'server.js'], cwd: '', color: '\x1b[32m' }],
  process.cwd(),
  7474,
);
await supervisor.start();
supervisor.controlEndpointPort;   // actual bound port (may be > 7474)
